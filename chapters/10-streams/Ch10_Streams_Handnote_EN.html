SECTION 01

Returning an Optional

An Optional<T> is a box that may contain a value or may be empty. It expresses "we don't know / not applicable" cleanly — e.g., the average of zero exam scores isn't 0; it simply doesn't exist.

Creating an Optional

Optional uses a factory pattern — it has no public constructor. Three static factories:

public static Optional<Double> average(int… scores) {
   if (scores.length == 0) return Optional.empty();
   int sum = 0;
   for (int score : scores) sum += score;
   return Optional.of((double) sum / scores.length);
}
System.out.println(average(90, 100)); // Optional[95.0]
System.out.println(average());        // Optional.empty

Wrapping a possibly-null value? The ternary pattern (value == null) ? Optional.empty() : Optional.of(value) is so common that Java provides:

Optional o = Optional.ofNullable(value);
⚠ Exam Trap Calling get() on an empty Optional throws NoSuchElementException at runtime. Always guard with isPresent() — or use a safer method below.

Instance methods you must know

MethodWhen Optional is emptyWhen Optional contains value
get()Throws exceptionReturns value
ifPresent(Consumer c)Does nothingCalls Consumer with value
isPresent()Returns falseReturns true

Dealing with an empty Optional

Optional<Double> opt = average();
System.out.println(opt.orElse(Double.NaN));            // NaN
System.out.println(opt.orElseGet(() -> Math.random()));// e.g. 0.4977…
System.out.println(opt.orElseThrow());                 // NoSuchElementException
System.out.println(opt.orElseThrow(
   () -> new IllegalStateException()));               // IllegalStateException

Note in orElseThrow(Supplier) you do not write throw new … — the Supplier merely creates the exception; orElseThrow() throws it for you.

⚠ Exam Trap — orElseGet type mismatch 
System.out.println(opt.orElseGet(
   () -> new IllegalStateException())); // DOES NOT COMPILE
opt is an Optional<Double>, so the Supplier must return a Double. A Supplier returning an exception is a type mismatch. Don't confuse orElseGet (returns a fallback value) with orElseThrow (creates an exception).
✓ Key Rule If the Optional has a value, all of orElse(…), orElseGet(…), and orElseThrow(…) simply return the value — the "or else" logic never runs. average(90,100) prints 95.0 three times through all three methods.
SECTION 02

The Stream Pipeline Flow

A stream is a sequence of data; a stream pipeline is the set of operations that run on it to produce a result. Think of it as an assembly line: each worker (operation) handles one element and passes it on — once an element passes a station, it doesn't come back. Data is created when needed: this is lazy evaluation.

Every pipeline has three parts:

  • Source — where the stream comes from.
  • Intermediate operations — transform the stream into another stream. Zero or many; they do not run until the terminal operation runs.
  • Terminal operation — produces a result. A stream can be used only once; after the terminal operation completes, the stream is no longer valid.

Intermediate vs. terminal — the exam wants this cold

ScenarioIntermediate operationTerminal operation
Required part of useful pipeline?NoYes
Can exist multiple times in pipeline?YesNo
Return type is stream type?YesNo
Executed upon method call?NoYes
Stream valid after call?YesNo
★ Remember — the foreperson Java acts as a factory foreperson: it reads the whole pipeline first, sets up the workers, and only starts them when it sees the terminal operation. With a limit(2) in the pipeline, the foreperson stops the line as soon as two elements pass — remaining elements in the source are never processed. This is why lazy evaluation makes infinite streams usable.
SECTION 03

Creating Stream Sources

Streams live in java.util.stream; the object stream interface is Stream<T>.

Finite streams

Stream<String>  empty         = Stream.empty();          // count = 0
Stream<Integer> singleElement = Stream.of(1);            // count = 1
Stream<Integer> fromArray     = Stream.of(1, 2, 3);      // count = 3 (varargs)

var list = List.of("a", "b", "c");
Stream<String> fromList         = list.stream();
Stream<String> fromListParallel = list.parallelStream(); // parallel variant

Infinite streams

Stream<Double>  randoms    = Stream.generate(Math::random);
Stream<Integer> oddNumbers = Stream.iterate(1, n -> n + 2);

Stream<Integer> oddUnder100 = Stream.iterate(

SECTION 04

Common Terminal Operations

A terminal operation can exist without intermediate operations, but not the other way around. A reduction is a special terminal operation that combines the entire stream contents into a single primitive or Object.

MethodInfinite streamsReturn valueReduction?
count()Does not terminatelongYes
min() / max()Does not terminateOptional<T>Yes
findAny() / findFirst()TerminatesOptional<T>No
allMatch() / anyMatch() / noneMatch()Sometimes terminatesbooleanNo
forEach()Does not terminatevoidNo
reduce()Does not terminateVariesYes
collect()Does not terminateVariesYes

count(), min() and max()

Stream<String> s = Stream.of("monkey", "gorilla", "bonobo");
System.out.println(s.count()); // 3

Stream<String> t = Stream.of("monkey", "ape", "bonobo");
Optional<String> min = t.min((s1, s2) -> s1.length() - s2.length());
min.ifPresent(System.out::println); // ape

Optional<?> minEmpty = Stream.empty().min((s1, s2) -> 0);
System.out.println(minEmpty.isPresent()); // false
✓ Key Rule You can't get both min and max from the same stream with these methods — one terminal operation per stream. (Primitive streams solve this with summaryStatistics(), Section 08.)

findAny() / findFirst()

Return an element in an Optional (empty Optional for an empty stream). These are the first methods that can terminate on an infinite stream — only one element needs generating. findAny() commonly returns the first element on serial streams, but that is not guaranteed (especially with parallel streams). They are terminal operations but not reductions, since they may not process all elements.

Stream<String> infinite = Stream.generate(() -> "chimp");
infinite.findAny().ifPresent(System.out::println); // chimp

Matching

var list = List.of("monkey", "2", "chimp");
Stream<String> infinite = Stream.generate(() -> "chimp");
Predicate<String> pred = x -> Character.isLetter(x.charAt(0));

System.out.println(list.stream().anyMatch(pred));  // true
System.out.println(list.stream().allMatch(pred));  // false
System.out.println(list.stream().noneMatch(pred)); // false
System.out.println(infinite.anyMatch(pred));       // true
⚠ Exam Trap — sometimes hangs allMatch(), anyMatch(), noneMatch() may or may not terminate on infinite streams — it depends on the data. infinite.anyMatch(pred) above returns true immediately; but infinite.allMatch(pred) never terminates because every element matches, so it must check them all.
★ Remember Match methods return a boolean; find methods return an Optional (they return an actual element).

forEach()

The only terminal operation with a void return. Doesn't terminate on infinite streams.

Stream<String> s = Stream.of("Monkey", "Gorilla", "Bonobo");
s.forEach(System.out::print); // MonkeyGorillaBonobo

Stream<Integer> s2 = Stream.of(1);
for (Integer i : s2) {} // DOES NOT COMPILE
⚠ Exam Trap A Stream cannot be the source of a for-each loop — streams do not implement Iterable. Also, forEach() exists on both Collection and Stream — don't be confused when you see either.

reduce() — three signatures

public T reduce(T identity, BinaryOperator<T> accumulator)
public Optional<T> reduce(BinaryOperator<T> accumulator)
public <U> U reduce(U identity, BiFunction<U,? super T,U> accumulator,
                    BinaryOperator<U> combiner)
Stream<String> stream = Stream.of("w", "o", "l", "f");
String word = stream.reduce("", (s, c) -> s + c);   // or String::concat
System.out.println(word); // wolf

Stream<Integer> nums = Stream.of(3, 5, 6);
System.out.println(nums.reduce(1, (a, b) -> a*b)); // 90

Without an identity, the result is an Optional<T> with three possible outcomes:

reduce(BinaryOperator) — Optional rules

  • Stream empty → empty Optional returned.
  • One element → that element is returned.
  • Multiple elements → the accumulator combines them.
BinaryOperator<Integer> op = (a, b) -> a * b;
Stream.<Integer>empty().reduce(op).ifPresent(System.out::println); // no output
Stream.of(3).reduce(op).ifPresent(System.out::println);            // 3
Stream.of(3, 5, 6).reduce(op).ifPresent(System.out::println);      // 90

The three-argument form handles different types and helps parallel streams (partial results are merged by the combiner):

Stream<String> stream = Stream.of("w", "o", "l", "f!");
int length = stream.reduce(0, (i, s) -> i + s.length(), (a, b) -> a + b);
System.out.println(length); // 5

collect() — mutable reduction

collect() accumulates into the same mutable object (e.g. StringBuilder, ArrayList) — more efficient than a regular reduction. Long form takes supplier, accumulator, combiner:

Stream<String> stream = Stream.of("w", "o", "l", "f");
StringBuilder word = stream.collect(
   StringBuilder::new,      // supplier
   StringBuilder::append,   // accumulator
   StringBuilder::append);  // combiner
System.out.println(word);   // wolf

Stream<String> s2 = Stream.of("w", "o", "l", "f");
TreeSet<String> set = s2.collect(TreeSet::new, TreeSet::add, TreeSet::addAll);
System.out.println(set);    // [f, l, o, w]

Or pass a predefined Collector from the Collectors class:

TreeSet<String> set = stream.collect(Collectors.toCollection(TreeSet::new));
Set<String>     any = stream.collect(Collectors.toSet()); // no guaranteed impl/order
★ Remember Collectors.toSet() gives no guarantee about the Set implementation you get. The exam expects you to know common predefined collectors and to write your own supplier/accumulator/combiner triple.
SECTION 05

Common Intermediate Operations

An intermediate operation produces a stream as its result, and can happily handle an infinite stream by returning another infinite stream (elements are produced only as needed).

filter(), distinct(), limit() & skip()

Stream.of("monkey", "gorilla", "bonobo")
   .filter(x -> x.startsWith("m"))
   .forEach(System.out::print);       // monkey

Stream.of("duck", "duck", "duck", "goose")
   .distinct()                        // uses equals(); dups need not be adjacent
   .forEach(System.out::print);       // duckgoose

Stream<Integer> s = Stream.iterate(1, n -> n + 1);  // infinite: 1,2,3,…
s.skip(5)      // now starts at 6
 .limit(2)     // finite: two elements
 .forEach(System.out::print);         // 67
✓ Key Rule limit() can turn an infinite stream into a finite one. skip(n) drops the first n elements but leaves an infinite stream infinite.

map() and flatMap()

Stream.of("monkey", "gorilla", "bonobo")
   .map(String::length)
   .forEach(System.out::print);       // 676

map() is a one-to-one transformation via Function<T,R>. Don't confuse it with the Map interface. flatMap() lifts nested elements to the top level of a single stream, and removes empty elements:

List<String> zero = List.of();
var one = List.of("Bonobo");
var two = List.of("Mama Gorilla", "Baby Gorilla");
Stream<List<String>> animals = Stream.of(zero, one, two);

animals.flatMap(m -> m.stream())
   .forEach(System.out::println);
// Bonobo
// Mama Gorilla
// Baby Gorilla
★ Remember — Stream.concat() To concatenate exactly two streams, Stream.concat(one, two) is more convenient than flatMap().

sorted()

Stream.of("brown-", "bear-").sorted()
   .forEach(System.out::print);                    // bear-brown-

Stream.of("brown bear-", "grizzly-")
   .sorted(Comparator.reverseOrder())
   .forEach(System.out::print);                    // grizzly-brown bear-

s.sorted(Comparator::reverseOrder); // DOES NOT COMPILE
⚠ Exam Trap — Comparator::reverseOrder sorted() needs a Comparator (two params → int). But Comparator::reverseOrder refers to a method that takes no arguments and returns a Comparator — it's equivalent to () -> Comparator.reverseOrder(), i.e., a Supplier<Comparator>. Wrong functional shape → compile error. Comparator.reverseOrder() (with parentheses) is correct.

peek()

An intermediate "forEach" for debugging: performs a Consumer on each element flowing past, then passes the same element on.

var stream = Stream.of("black bear", "brown bear", "grizzly");
long count = stream.filter(s -> s.startsWith("g"))
   .peek(System.out::println).count();   // grizzly
System.out.println(count);               // 1
⚠ Exam Trap — peek() with side effects 
var numbers = new ArrayList<>(); numbers.add(1);
var letters = new ArrayList<>(); letters.add('a');
Stream<List<?>> stream = Stream.of(numbers, letters);
stream.map(List::size).forEach(System.out::print);   // 11

Stream<List<?>> bad = Stream.of(numbers, letters);
bad.peek(x -> x.remove(0))
   .map(List::size)
   .forEach(System.out::print);                      // 00
Java doesn't stop you from mutating data inside peek() — but it changes the pipeline's result. Bad practice; the exam still shows it.
SECTION 06

Putting Together the Pipeline

Streams let you express what you want rather than how. First two 4-letter names, alphabetically:

var list = List.of("Toby", "Anna", "Leroy", "Alex");
list.stream()
   .filter(n -> n.length() == 4)
   .sorted()
   .limit(2)
   .forEach(System.out::println);  // Alex Anna
Trace (foreperson's view):
  1. Toby passes filter → held by sorted() (needs all data before sorting).
  2. Anna passes filter → held by sorted().
  3. Leroy fails filter → removed from the line.
  4. Alex passes filter → held by sorted().
  5. Source exhausted → sorted() sorts everything at once.
  6. Alex → limit() counts 1 → forEach prints Alex.
  7. Anna → limit() counts 2 → prints Anna.
  8. limit() reached its quota → foreperson stops the line.

Three infinite-stream classics

Stream.generate(() -> "Elsa")
   .filter(n -> n.length() == 4)
   .sorted().limit(2)
   .forEach(System.out::println);  // hangs (or OutOfMemory)

sorted() must see all elements before emitting anything — impossible on an infinite stream sitting before the limit().

Stream.generate(() -> "Elsa")
   .filter(n -> n.length() == 4)
   .limit(2).sorted()
   .forEach(System.out::println);  // Elsa
                                   // Elsa

Here limit(2) makes the stream finite before the sort → prints Elsa twice.

Stream.generate(() -> "Olaf Lazisson")
   .filter(n -> n.length() == 4)
   .limit(2).sorted()
   .forEach(System.out::println);  // hangs

The filter never lets anything through, so limit(2) never sees two elements — the pipeline waits forever.

✓ Key Rule On infinite streams, ask two questions: (1) is there a limit() before any all-elements operation like sorted()? (2) can the filter actually deliver enough elements to satisfy the limit? Both must be yes or the code hangs.

Chained pipelines

30: long count = Stream.of("goldfish", "finch")
31:    .filter(s -> s.length() > 5)
32:    .collect(Collectors.toList())
33:    .stream()
34:    .count();
35: System.out.println(count);   // 1

Two pipelines: lines 30–32 (source line 30, terminal collect line 32) and lines 33–34 (source line 33, terminal count line 34). Only goldfish (8 letters) survives the filter, so the count is 1. On long answer options, focus on the differences between the choices — that's where the answer hides.

SECTION 07

Working with Primitive Streams

Three primitive stream interfaces exist:

  • IntStream — for int, short, byte, and char
  • LongStream — for long
  • DoubleStream — for double and float

Why? Numeric convenience methods:

Stream<Integer> stream = Stream.of(1, 2, 3);
System.out.println(stream.mapToInt(x -> x).sum());  // 6

IntStream intStream = IntStream.of(1, 2, 3);
OptionalDouble avg = intStream.average();
System.out.println(avg.getAsDouble());              // 2.0
★ Remember — case matters Capital-S Stream is the object-stream interface. Lowercase "stream" is the concept, covering Stream, IntStream, LongStream, and DoubleStream.

Creating primitive streams

DoubleStream empty    = DoubleStream.empty();
DoubleStream oneValue = DoubleStream.of(3.14);
DoubleStream varargs  = DoubleStream.of(1.0, 1.1, 1.2);
var random    = DoubleStream.generate(Math::random);   // infinite
var fractions = DoubleStream.iterate(.5, d -> d / 2);  // infinite

range() and rangeClosed()

IntStream.iterate(1, n -> n + 1).limit(5)
   .forEach(System.out::print);          // 12345 (verbose)
IntStream.range(1, 6)
   .forEach(System.out::print);          // 12345 (6 exclusive)
IntStream.rangeClosed(1, 5)
   .forEach(System.out::print);          // 12345 (5 inclusive)
✓ Key Rule range(a, b): a inclusive, b exclusive. rangeClosed(a, b): both inclusive. Only on IntStream and LongStream — not DoubleStream.

Mapping between stream types — memorize both tables

  • Same type → just map(). Target is an object stream → mapToObj(). Otherwise → mapTo + primitive name.
  • Function names: target is an object → drop the "To" (IntFunction, not IntToObjFunction). Same primitive type → UnaryOperator, not Function.

Stream<Integer> a = ints.mapToObj(x -> x);

Primitive Optionals & Summary Statistics

Primitive streams return primitive optionals: OptionalDouble, OptionalInt, OptionalLong (for primitives, vs Optional<Double> for the wrapper).

OptionalDouble optional = stream.average();
optional.ifPresent(System.out::println);                  // 5.5
System.out.println(optional.getAsDouble());               // 5.5
System.out.println(optional.orElseGet(() -> Double.NaN)); // 5.5

5: LongStream longs = LongStream.of(5, 10);
6: long sum = longs.sum();
7: System.out.println(sum);     // 15
8: DoubleStream doubles = DoubleStream.generate(() -> Math.PI);

Summary statistics — min AND max from one stream

Since a stream allows only one terminal operation, you can't call min() and max() on the same stream. summaryStatistics() computes them all in a single pass:

private static int range(IntStream ints) {
   IntSummaryStatistics stats = ints.summaryStatistics();
   if (stats.getCount() == 0) throw new RuntimeException();
   return stats.getMax() - stats.getMin();
}

Summary statistics getters (know the empty-stream values!)

  • getCount() → long count of values.
  • getAverage() → double; empty stream → 0.0.
  • getSum() → double for DoubleSummaryStatistics; long for Int/Long.
  • getMin() → smallest number (double/int/long); empty stream → the largest numeric value of the type.
  • getMax() → largest number; empty stream → the smallest numeric value of the type.
SECTION 09

Lazy Data Link & Chaining Optionals

Streams are linked to the underlying data

25: var cats = new ArrayList<String>();
26: cats.add("Annie");
27: cats.add("Ripley");
28: var stream = cats.stream();
29: cats.add("KC");
30: System.out.println(stream.count());  // 3
⚠ Exam Trap The answer is 3, not 2. Line 28 doesn't materialize the stream — it creates an object that knows where to look when needed. The element added on line 29 is visible when the pipeline actually runs on line 30. Lazy evaluation!

Chaining Optionals

MethodWhen Optional is emptyWhen Optional contains value
filter(Predicate p)Returns empty OptionalOptional with the element if it matches, otherwise empty Optional
flatMap(Function f)Returns empty OptionalOptional with Function applied; Function's return type must inherit Optional
map(Function f)Returns empty OptionalOptional with Function applied
private static void threeDigit(Optional<Integer> optional) {
   optional.map(n -> "" + n)           // part 1
      .filter(s -> s.length() == 3)    // part 2
      .ifPresent(System.out::println); // part 3
}
Trace — three inputs:
  • Empty Optional: map() and filter() pass the empty box through; ifPresent() does nothing.
  • Optional.of(4): mapped to "4"; filter fails (length 1) → empty Optional; nothing prints.
  • Optional.of(123): mapped to "123"; filter passes; ifPresent prints 123.
⚠ Exam Trap — map vs flatMap on Optional 
// helper returns Optional<Integer>
Optional<Integer> result = optional
   .map(ChainingOptionals::calculator);     // DOES NOT COMPILE
Optional<Integer> result = optional
   .flatMap(ChainingOptionals::calculator); // OK
If the mapped method itself returns an Optional<Integer>, map() wraps it again → Optional<Optional<Integer>>, which doesn't match the declared type. flatMap() flattens the extra layer.
★ Remember — checked exceptions & functional interfaces Supplier (like most functional interfaces) declares no checked exceptions. So Supplier<List<String>> s = ExceptionCaseStudy::create; DOES NOT COMPILE when create() throws IOException — even inside a method that declares throws IOException. Fix: catch inside the lambda and rethrow unchecked, or wrap in a safe helper method and reference that.
SECTION 10

Collecting Results — Basic Collectors & toMap

Predefined collectors are static methods on the Collectors class (a class of helpers, like Collections) — passed into collect(). A Collector does nothing on its own.

var ohMy = Stream.of("lions", "tigers", "bears");
String result = ohMy.collect(Collectors.joining(", "));
System.out.println(result); // lions, tigers, bears

Double avg = ohMy2.collect(Collectors.averagingInt(String::length));
System.out.println(avg);    // 5.333333333333333

TreeSet<String> ts = ohMy3.filter(s -> s.startsWith("t"))
   .collect(Collectors.toCollection(TreeSet::new)); // [tigers]
★ Remember Collector averaging methods return the wrapper Double (an Object is needed), whereas primitive-stream average() returns OptionalDouble.
⚠ Exam Trap — toList() vs Collectors.toList() 
List<String> mutableList   = stream1.collect(Collectors.toList());
List<String> immutableList = stream2.toList();
mutableList.add("zebras");   // No issues
immutableList.add("zebras"); // UnsupportedOperationException
Collectors.toList() → mutable list. The shortcut stream.toList() → list that does not allow changes.

Collecting into Maps — toMap()

var ohMy = Stream.of("lions", "tigers", "bears");
Map<String, Integer> map = ohMy.collect(
   Collectors.toMap(s -> s, String::length));
System.out.println(map); // {lions=5, bears=5, tigers=6}

First function → key; second function → value. s -> s can be written Function.identity().

⚠ Exam Trap — duplicate keys 
Map<Integer, String> map = ohMy.collect(Collectors.toMap(
   String::length, k -> k));  // BAD
// java.lang.IllegalStateException: Duplicate key 5
//   (attempted merging values lions and bears)
"lions" and "bears" both have length 5. With no merge function, the collector throws IllegalStateException at runtime (compiles fine!). 
// Fix: merge function (3rd arg); force map type with a supplier (4th arg)
TreeMap<Integer, String> map = ohMy.collect(Collectors.toMap(
   String::length,
   k -> k,
   (s1, s2) -> s1 + "," + s2,
   TreeMap::new));
System.out.println(map);            // {5=lions,bears, 6=tigers}
System.out.println(map.getClass()); // class java.util.TreeMap
✓ Key Rule Without a supplier, the returned Map happens to be a HashMap, but this is not guaranteed — never rely on it.
SECTION 11

Grouping, Partitioning, Mapping & Teeing

The exam creators love groupingBy() and partitioningBy().

groupingBy()

var ohMy = Stream.of("lions", "tigers", "bears");
Map<Integer, List<String>> map = ohMy.collect(
   Collectors.groupingBy(String::length));
System.out.println(map); // {5=[lions, bears], 6=[tigers]}

// Downstream collector: values become a Set
Map<Integer, Set<String>> map2 = ohMy2.collect(
   Collectors.groupingBy(String::length, Collectors.toSet()));

// Map-type supplier + downstream collector
TreeMap<Integer, Set<String>> map3 = ohMy3.collect(
   Collectors.groupingBy(String::length, TreeMap::new, Collectors.toSet()));

// Count per group
Map<Integer, Long> map4 = ohMy4.collect(
   Collectors.groupingBy(String::length, Collectors.counting()));
System.out.println(map4); // {5=2, 6=1}
⚠ Exam Trap The function passed to groupingBy() cannot return null — null keys are not allowed. Also note counting() yields Long, not Integer.

partitioningBy()

Map<Boolean, List<String>> map = ohMy.collect(
   Collectors.partitioningBy(s -> s.length() <= 5));
System.out.println(map); // {false=[tigers], true=[lions, bears]}

Map<Boolean, List<String>> map2 = ohMy2.collect(
   Collectors.partitioningBy(s -> s.length() <= 7));
System.out.println(map2); // {false=[], true=[lions, tigers, bears]}

partitioningBy() — the rules

  • A special case of grouping with exactly two groups: true and false.
  • The Map always has both keys, even if one value is an empty list.
  • A downstream collector may change the value type (e.g. Collectors.toSet()).
  • Unlike groupingBy(), you cannot change the Map type returned.
  • Keys are Boolean (wrapper) — generics can't hold primitive boolean.

groupingBy(Function)

  • Keys determined by your function (any type).
  • Only groups with matches appear in the Map.
  • Optional downstream collector and Map supplier.
  • Function must not return null.

partitioningBy(Predicate)

  • Keys are always true / false.
  • Both keys always present, possibly with empty values.
  • Optional downstream collector, but no Map supplier.
  • Takes a Predicate, not a Function.

mapping() — a collector inside a collector

Map<Integer, Optional<Character>> map = ohMy.collect(
   Collectors.groupingBy(
      String::length,
      Collectors.mapping(
         s -> s.charAt(0),
         Collectors.minBy((a, b) -> a - b))));
System.out.println(map); // {5=Optional[b], 6=Optional[t]}

mapping() takes two parameters: the function for the value and how to group it further. You may see this with static imports (groupingBy(…, mapping(…, minBy(…)))) and var — recognize the collector names without the Collectors. prefix.

teeing() — return two things from one pass

record Separations(String spaceSeparated, String commaSeparated) {}

var list = List.of("x", "y", "z");
Separations result = list.stream()
   .collect(Collectors.teeing(
      Collectors.joining(" "),
      Collectors.joining(","),
      (s, c) -> new Separations(s, c)));
System.out.println(result);
// Separations[spaceSeparated=x y z, commaSeparated=x,y,z]
✓ Key Rule teeing(c1, c2, biFunction) feeds the stream to two collectors and merges both results into a single object — one pass, one return value, everybody's happy.

SECTION 12

Using a Spliterator

A Spliterator is a bag you can split: trySplit() takes roughly half the data out into a new Spliterator; the rest stays in the original. Implementing one isn't on the exam — using these three methods is:

MethodDescription
Spliterator<T> trySplit()Returns a Spliterator with ideally half the data, removed from the current one. Can be called repeatedly; eventually returns null when no longer splittable.
void forEachRemaining(Consumer<T> c)Processes all remaining elements.
boolean tryAdvance(Consumer<T> c)Processes a single element if any remain; returns whether an element was processed.
12: var stream = List.of("bird-", "bunny-", "cat-", "dog-", "fish-", "lamb-",
13:    "mouse-");
14: Spliterator<String> originalBagOfFood = stream.spliterator();
15: Spliterator<String> emmasBag = originalBagOfFood.trySplit();
16: emmasBag.forEachRemaining(System.out::print);  // bird-bunny-cat-
18: Spliterator<String> jillsBag = originalBagOfFood.trySplit();
19: jillsBag.tryAdvance(System.out::print);        // dog-
20: jillsBag.forEachRemaining(System.out::print);  // fish-
22: originalBagOfFood.forEachRemaining(System.out::print); // lamb-mouse-
Trace:
  • Start: 7 elements. trySplit() → Emma gets the front ~half: bird-, bunny-, cat- (3).
  • Original now has 4. Second trySplit() → Jill gets dog-, fish- (2).
  • tryAdvance prints one (dog-); forEachRemaining prints the rest of Jill's bag (fish-).
  • Original keeps lamb-, mouse- → printed last.
var originalBag = Stream.iterate(1, n -> ++n).spliterator();
Spliterator<Integer> newBag = originalBag.trySplit();
newBag.tryAdvance(System.out::print); // 1
newBag.tryAdvance(System.out::print); // 2
newBag.tryAdvance(System.out::print); // 3
✓ Key Rule On an infinite stream, trySplit() still works — the Spliterator won't try to take "half"; it returns a bag with a large number of elements. But calling forEachRemaining() on an infinite Spliterator is a very bad idea. A Stream-backed Spliterator is evaluated lazily; characteristics like CONCURRENT, ORDERED, SIZED, SORTED exist, but the exam shows only straightforward Spliterators.

★ Short Recap

Optional

  • Factories: empty(), of(), ofNullable(); no public constructor. get() on empty → NoSuchElementException.
  • orElse(value) / orElseGet(Supplier of value) / orElseThrow(no-arg or Supplier of exception).

Pipeline

  • Source + zero-or-more intermediate ops + exactly one terminal op; lazy evaluation; stream is single-use.

Terminal operations

  • Reductions: count, min, max, reduce, collect. Non-reductions: find/match/forEach. Only find (always) and match (sometimes) can finish on infinite streams.

Intermediate operations

  • filter, distinct, limit/skip, map, flatMap, sorted, peek. sorted() needs all elements — put limit() first for infinite streams.

Primitive streams

  • IntStream (int/short/byte/char), LongStream, DoubleStream; range (end exclusive) vs rangeClosed (end inclusive); mapToX/mapToObj/boxed; sum() → primitive (0 if empty), average() → always OptionalDouble.

Collectors

  • toMap duplicate key without merge → IllegalStateException. groupingBy: no null keys, supports Map supplier. partitioningBy: always two Boolean keys, no Map supplier. teeing: two collectors + merger. stream.toList() is unmodifiable; Collectors.toList() is mutable.

Spliterator

  • trySplit() removes ~half; tryAdvance() one element (returns boolean); forEachRemaining() the rest.

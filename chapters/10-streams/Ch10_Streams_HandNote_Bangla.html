SECTION 01

Optional রিটার্ন করা

Optional<T> হলো একটা বাক্স — ভেতরে value থাকতেও পারে, নাও থাকতে পারে (empty)। "জানা নেই / প্রযোজ্য নয়" — এই কথাটা Java-তে পরিষ্কারভাবে বলার উপায় এটা। যেমন: কোনো exam না দিলে average 0 না — average-টা আসলে নেই-ই।

Optional তৈরি করা

Optional factory pattern ব্যবহার করে — এর কোনো public constructor নেই। তিনটা static factory মনে রাখতে হবে:

public static Optional<Double> average(int… scores) {
   if (scores.length == 0) return Optional.empty();
   int sum = 0;
   for (int score : scores) sum += score;
   return Optional.of((double) sum / scores.length);
}
System.out.println(average(90, 100)); // Optional[95.0]
System.out.println(average());        // Optional.empty

Value null হতে পারে? Ternary pattern (value == null) ? Optional.empty() : Optional.of(value) এত common যে Java একটা shortcut দিয়েছে:

Optional o = Optional.ofNullable(value);
⚠ EXAM TRAP Empty Optional-এ get() কল করলে runtime-এ NoSuchElementException throw হয়। আগে isPresent() দিয়ে check করো — অথবা নিচের safer method-গুলো ব্যবহার করো।

যে instance method-গুলো জানতেই হবে

MethodOptional empty হলেOptional-এ value থাকলে
get()Exception throw করেValue রিটার্ন করে
ifPresent(Consumer c)কিছুই করে নাValue দিয়ে Consumer কল করে
isPresent()false রিটার্ন করেtrue রিটার্ন করে
orElse(T other)other parameter রিটার্ন করেValue রিটার্ন করে
orElseGet(Supplier s)Supplier কল করে তার result রিটার্ন করেValue রিটার্ন করে
orElseThrow()NoSuchElementException throw করেValue রিটার্ন করে
orElseThrow(Supplier s)Supplier-এর বানানো exception throw করেValue রিটার্ন করে

Empty Optional সামলানো

Optional<Double> opt = average();
System.out.println(opt.orElse(Double.NaN));            // NaN
System.out.println(opt.orElseGet(() -> Math.random()));// e.g. 0.4977…
System.out.println(opt.orElseThrow());                 // NoSuchElementException
System.out.println(opt.orElseThrow(
   () -> new IllegalStateException()));               // IllegalStateException

খেয়াল করো — orElseThrow(Supplier)-এ আমরা throw new … লিখি না। Supplier শুধু exception-টা তৈরি করে; throw করার কাজটা orElseThrow() নিজে করে।

⚠ EXAM TRAP — orElseGet-এ type mismatch 
System.out.println(opt.orElseGet(
   () -> new IllegalStateException())); // DOES NOT COMPILE
opt হলো Optional<Double> — তাই Supplier-কে অবশ্যই Double রিটার্ন করতে হবে। Exception রিটার্ন করা Supplier মানে type mismatch। orElseGet (fallback value দেয়) আর orElseThrow (exception বানায়) — এই দুটো গুলিয়ে ফেলো না।
✓ KEY RULE Optional-এ value থাকলে orElse(…), orElseGet(…), orElseThrow(…) — সবগুলোই কেবল value-টাই রিটার্ন করে; "or else" logic চলেই না। average(90,100)-এর ক্ষেত্রে তিনটা method-ই 95.0 প্রিন্ট করে।
SECTION 02

Stream Pipeline-এর ফ্লো

Stream হলো data-র একটা sequence; আর stream pipeline হলো সেই stream-এর ওপর চলা operation-গুলো, যেগুলো একটা result তৈরি করে। ভাবো একটা assembly line: প্রতিটা worker (operation) একটা element ধরে কাজ করে পরের জনকে দিয়ে দেয় — একবার পার হয়ে গেলে সেই element আর ফেরত আসে না। Data তৈরি হয় দরকার হলে তবেই — এটাই lazy evaluation।

প্রতিটা pipeline-এর তিনটা অংশ:

  • Source — stream কোথা থেকে আসছে।
  • Intermediate operations — stream-কে আরেকটা stream-এ transform করে। শূন্য থেকে যত খুশি থাকতে পারে; terminal operation না চলা পর্যন্ত এরা চলে না।
  • Terminal operation — result তৈরি করে। একটা stream একবারই ব্যবহারযোগ্য; terminal operation শেষ হলে stream-টা আর valid থাকে না।

Intermediate বনাম Terminal — পরীক্ষায় এটা মুখস্থ চাই

পরিস্থিতিIntermediate operationTerminal operation
কার্যকর pipeline-এর জন্য বাধ্যতামূলক?নাহ্যাঁ
Pipeline-এ একাধিকবার থাকতে পারে?হ্যাঁনা
Return type কি stream type?হ্যাঁনা
Method কল করলেই execute হয়?নাহ্যাঁ
কল করার পরও stream valid?হ্যাঁনা
★ REMEMBER — foreperson Java কাজ করে ফ্যাক্টরির foreperson-এর মতো: পুরো pipeline আগে পড়ে, worker-দের বসিয়ে দেয়, তারপর terminal operation দেখলে তবেই কাজ শুরুর নির্দেশ দেয়। Pipeline-এ limit(2) থাকলে দুটো element পার হওয়া মাত্র foreperson লাইন থামিয়ে দেয় — source-এর বাকি element-গুলো process-ই হয় না। Lazy evaluation-এর কারণেই infinite stream ব্যবহারযোগ্য।
SECTION 03

Stream Source তৈরি করা

Streams থাকে java.util.stream package-এ; object stream-এর interface হলো Stream<T>।

Finite streams

Stream<String>  empty         = Stream.empty();          // count = 0
Stream<Integer> singleElement = Stream.of(1);            // count = 1
Stream<Integer> fromArray     = Stream.of(1, 2, 3);      // count = 3 (varargs)

var list = List.of("a", "b", "c");
Stream<String> fromList         = list.stream();
Stream<String> fromListParallel = list.parallelStream(); // parallel variant

Infinite streams

Stream<Double>  randoms    = Stream.generate(Math::random);
Stream<Integer> oddNumbers = Stream.iterate(1, n -> n + 2);

Stream<Integer> oddUnder100 = Stream.iterate(
   1,              // seed
   n -> n < 100,   // Predicate to specify when done
   n -> n + 2);    // UnaryOperator to get next value
⚠ EXAM TRAP 3-arg iterate()-এর parameter-গুলো আলাদা হয় কমা (,) দিয়ে — যেকোনো method call-এর মতোই। পরীক্ষা for loop-এর মতো দেখাতে semicolon ঢুকিয়ে দিতে পারে — সেটা compile হবে না। আরও: stream reference সরাসরি প্রিন্ট করলে contents নয়, আসে java.util.stream.ReferencePipeline$3@4517d9a3-এর মতো কিছু।
MethodFinite না infinite?নোট
Stream.empty()Finiteশূন্য element-এর Stream।
Stream.of(varargs)Finiteদেওয়া element-গুলোর Stream।
coll.stream()FiniteCollection থেকে Stream।
coll.parallelStream()FiniteCollection থেকে Stream, যা parallel-এ চলতে পারে।

SECTION 04

Common Terminal Operations

Intermediate operation ছাড়া terminal operation চলতে পারে, কিন্তু উল্টোটা না। Reduction হলো বিশেষ ধরনের terminal operation — stream-এর সব content মিলিয়ে একটা single primitive বা Object বানায়।

MethodInfinite stream-এReturn valueReduction?
count()Terminate হয় নাlongহ্যাঁ
min() / max()Terminate হয় নাOptional<T>হ্যাঁ
findAny() / findFirst()Terminate হয়Optional<T>না
allMatch() / anyMatch() / noneMatch()কখনো হয়, কখনো নাbooleanনা
forEach()Terminate হয় নাvoidনা
reduce()Terminate হয় নাভিন্ন হয়হ্যাঁ
collect()Terminate হয় নাভিন্ন হয়হ্যাঁ

count(), min() ও max()

Stream<String> s = Stream.of("monkey", "gorilla", "bonobo");
System.out.println(s.count()); // 3

Stream<String> t = Stream.of("monkey", "ape", "bonobo");
Optional<String> min = t.min((s1, s2) -> s1.length() - s2.length());
min.ifPresent(System.out::println); // ape

Optional<?> minEmpty = Stream.empty().min((s1, s2) -> 0);
System.out.println(minEmpty.isPresent()); // false
✓ KEY RULE এই method-গুলো দিয়ে একই stream থেকে min এবং max দুটোই পাওয়া যায় না — প্রতি stream-এ terminal operation একটাই। (Primitive streams এই সমস্যা মেটায় summaryStatistics() দিয়ে — Section 08।)

findAny() / findFirst()

একটা element রিটার্ন করে Optional-এ মুড়ে (empty stream হলে empty Optional)। এরাই প্রথম method যারা infinite stream-এও terminate করতে পারে — কারণ একটা element generate হলেই কাজ শেষ। Serial stream-এ findAny() সাধারণত প্রথম element-ই দেয়, কিন্তু সেটা guaranteed না (parallel stream-এ বিশেষভাবে)। এরা terminal operation, কিন্তু reduction নয় — সব element process না করেই ফিরতে পারে।

Stream<String> infinite = Stream.generate(() -> "chimp");
infinite.findAny().ifPresent(System.out::println); // chimp

Matching

var list = List.of("monkey", "2", "chimp");
Stream<String> infinite = Stream.generate(() -> "chimp");
Predicate<String> pred = x -> Character.isLetter(x.charAt(0));

System.out.println(list.stream().anyMatch(pred));  // true
System.out.println(list.stream().allMatch(pred));  // false
System.out.println(list.stream().noneMatch(pred)); // false
System.out.println(infinite.anyMatch(pred));       // true
⚠ EXAM TRAP — কখনো hang করে allMatch(), anyMatch(), noneMatch() — infinite stream-এ terminate হতেও পারে, নাও পারে; নির্ভর করে data-র ওপর। উপরের infinite.anyMatch(pred) সাথে সাথে true দেয়; কিন্তু infinite.allMatch(pred) কখনোই terminate করে না — সব element match করে বলে ওকে সবগুলোই দেখতে হয়।
★ REMEMBER Match method-গুলো boolean রিটার্ন করে; find method-গুলো Optional (কারণ ওরা stream-এর একটা element ফেরত দেয়)।

forEach()

একমাত্র terminal operation যার return type void। Infinite stream-এ terminate হয় না।

Stream<String> s = Stream.of("Monkey", "Gorilla", "Bonobo");
s.forEach(System.out::print); // MonkeyGorillaBonobo

Stream<Integer> s2 = Stream.of(1);
for (Integer i : s2) {} // DOES NOT COMPILE
⚠ EXAM TRAP Stream কখনো for-each loop-এর source হতে পারে না — streams Iterable implement করে না। আরেকটা কথা: forEach() আছে Collection এবং Stream — দুটোতেই; পরীক্ষায় দুটো দেখে ঘাবড়ে যেও না।

reduce() — তিনটা signature

public T reduce(T identity, BinaryOperator<T> accumulator)
public Optional<T> reduce(BinaryOperator<T> accumulator)
public <U> U reduce(U identity, BiFunction<U,? super T,U> accumulator,
                    BinaryOperator<U> combiner)
Stream<String> stream = Stream.of("w", "o", "l", "f");
String word = stream.reduce("", (s, c) -> s + c);   // or String::concat
System.out.println(word); // wolf

Stream<Integer> nums = Stream.of(3, 5, 6);
System.out.println(nums.reduce(1, (a, b) -> a*b)); // 90

Identity হলো reduction-এর initial value; accumulator current result-এর সাথে stream-এর পরের value-টা merge করে। Identity ছাড়া version-টা Optional<T> দেয় — তিন রকম ফল হতে পারে:

reduce(BinaryOperator) — Optional-এর নিয়ম

  • Stream empty → empty Optional।
  • একটা element → সেটাই রিটার্ন হয়।
  • একাধিক element → accumulator দিয়ে combine হয়।
BinaryOperator<Integer> op = (a, b) -> a * b;
Stream.<Integer>empty().reduce(op).ifPresent(System.out::println); // no output
Stream.of(3).reduce(op).ifPresent(System.out::println);            // 3
Stream.of(3, 5, 6).reduce(op).ifPresent(System.out::println);      // 90

তিন-argument form ভিন্ন type সামলায়, আর parallel stream-এ সুবিধা দেয় (আলাদা thread-এর partial result গুলো combiner জোড়া দেয়):

Stream<String> stream = Stream.of("w", "o", "l", "f!");
int length = stream.reduce(0, (i, s) -> i + s.length(), (a, b) -> a + b);
System.out.println(length); // 5

collect() — mutable reduction

collect() হলো mutable reduction — accumulate করার সময় একই mutable object (যেমন StringBuilder, ArrayList) ব্যবহার করে বলে regular reduction-এর চেয়ে efficient। Long form নেয় supplier, accumulator, combiner:

Stream<String> stream = Stream.of("w", "o", "l", "f");
StringBuilder word = stream.collect(
   StringBuilder::new,      // supplier
   StringBuilder::append,   // accumulator
   StringBuilder::append);  // combiner
System.out.println(word);   // wolf

Stream<String> s2 = Stream.of("w", "o", "l", "f");
TreeSet<String> set = s2.collect(TreeSet::new, TreeSet::add, TreeSet::addAll);
System.out.println(set);    // [f, l, o, w]

অথবা Collectors class-এর predefined Collector pass করা যায়:

TreeSet<String> set = stream.collect(Collectors.toCollection(TreeSet::new));
Set<String>     any = stream.collect(Collectors.toSet()); // impl/order guaranteed না
★ REMEMBER Collectors.toSet() কোন Set implementation দেবে তার কোনো guarantee নেই। পরীক্ষায় predefined collectors এবং নিজের supplier/accumulator/combiner — দুটোই জানতে হবে।
SECTION 05

Common Intermediate Operations

Intermediate operation result হিসেবে একটা stream দেয়, আর infinite stream-ও দিব্যি সামলায় — আরেকটা infinite stream রিটার্ন করে (element তৈরি হয় শুধু দরকারমতো)।

filter(), distinct(), limit() ও skip()

Stream.of("monkey", "gorilla", "bonobo")
   .filter(x -> x.startsWith("m"))
   .forEach(System.out::print);       // monkey

Stream.of("duck", "duck", "duck", "goose")
   .distinct()                        // equals() ব্যবহার করে; পাশাপাশি থাকা লাগে না
   .forEach(System.out::print);       // duckgoose

Stream<Integer> s = Stream.iterate(1, n -> n + 1);  // infinite: 1,2,3,…
s.skip(5)      // এখন শুরু 6 থেকে
 .limit(2)     // finite: দুটো element
 .forEach(System.out::print);         // 67
✓ KEY RULE limit() infinite stream-কে finite বানাতে পারে। skip(n) প্রথম nটা element বাদ দেয়, কিন্তু infinite stream তখনও infinite-ই থাকে।

map() ও flatMap()

Stream.of("monkey", "gorilla", "bonobo")
   .map(String::length)
   .forEach(System.out::print);       // 676

map() হলো Function<T,R> দিয়ে one-to-one transformation। Map interface-এর সাথে গুলিও না। আর flatMap() nested element-গুলোকে একটা stream-এর top level-এ তুলে আনে, empty element বাদ দিয়ে:

List<String> zero = List.of();
var one = List.of("Bonobo");
var two = List.of("Mama Gorilla", "Baby Gorilla");
Stream<List<String>> animals = Stream.of(zero, one, two);

animals.flatMap(m -> m.stream())
   .forEach(System.out::println);
// Bonobo
// Mama Gorilla
// Baby Gorilla
★ REMEMBER — Stream.concat() ঠিক দুটো stream জোড়া দিতে Stream.concat(one, two) — flatMap()-এর চেয়ে সুবিধাজনক।

sorted()

Stream.of("brown-", "bear-").sorted()
   .forEach(System.out::print);                    // bear-brown-

Stream.of("brown bear-", "grizzly-")
   .sorted(Comparator.reverseOrder())
   .forEach(System.out::print);                    // grizzly-brown bear-

s.sorted(Comparator::reverseOrder); // DOES NOT COMPILE
⚠ EXAM TRAP — Comparator::reverseOrder sorted()-এর দরকার একটা Comparator (দুই parameter → int)। কিন্তু Comparator::reverseOrder এমন একটা method-কে refer করে যেটা কোনো argument নেয় না, একটা Comparator রিটার্ন করে — মানে () -> Comparator.reverseOrder(), অর্থাৎ একটা Supplier<Comparator>। ভুল functional shape → compile error। ঠিকটা: Comparator.reverseOrder() (parentheses সহ)।

peek()

Debugging-এর জন্য intermediate "forEach": প্রতিটা element-এর ওপর একটা Consumer চালিয়ে একই element সামনে পাঠিয়ে দেয়।

var stream = Stream.of("black bear", "brown bear", "grizzly");
long count = stream.filter(s -> s.startsWith("g"))
   .peek(System.out::println).count();   // grizzly
System.out.println(count);               // 1
⚠ EXAM TRAP — peek()-এ side effect 
var numbers = new ArrayList<>(); numbers.add(1);
var letters = new ArrayList<>(); letters.add('a');
Stream<List<?>> stream = Stream.of(numbers, letters);
stream.map(List::size).forEach(System.out::print);   // 11

Stream<List<?>> bad = Stream.of(numbers, letters);
bad.peek(x -> x.remove(0))
   .map(List::size)
   .forEach(System.out::print);                      // 00
peek()-এর ভেতরে data structure বদলানো Java আটকায় না — কিন্তু তাতে pipeline-এর result পাল্টে যায়। Bad practice, তবু পরীক্ষায় দেখাবে।
SECTION 06

পুরো Pipeline একসাথে

Streams দিয়ে আমরা কীভাবে নয়, কী চাই সেটা প্রকাশ করি। ৪ অক্ষরের নামগুলোর মধ্যে alphabetically প্রথম দুটো:

var list = List.of("Toby", "Anna", "Leroy", "Alex");
list.stream()
   .filter(n -> n.length() == 4)
   .sorted()
   .limit(2)
   .forEach(System.out::println);  // Alex Anna
Trace (foreperson-এর চোখে):
  1. Toby filter পার হয় → sorted() ওকে ধরে রাখে (sort করার আগে সব data চাই)।
  2. Anna filter পার হয় → sorted() ধরে রাখে।
  3. Leroy filter-এ বাদ → লাইন থেকে সরে যায়।
  4. Alex filter পার হয় → sorted() ধরে রাখে।
  5. Source শেষ → sorted() একবারে সব sort করে।
  6. Alex → limit() গোনে ১ → forEach Alex প্রিন্ট করে।
  7. Anna → limit() গোনে ২ → Anna প্রিন্ট হয়।
  8. limit()-এর কোটা পূর্ণ → foreperson লাইন থামিয়ে দেয়।

Infinite stream-এর তিনটা ক্লাসিক উদাহরণ

Stream.generate(() -> "Elsa")
   .filter(n -> n.length() == 4)
   .sorted().limit(2)
   .forEach(System.out::println);  // hangs (বা OutOfMemory)

sorted()-কে কিছু emit করার আগে সব element দেখতে হয় — আর limit()-এর আগে বসা infinite stream-এ সেটা অসম্ভব।

Stream.generate(() -> "Elsa")
   .filter(n -> n.length() == 4)
   .limit(2).sorted()
   .forEach(System.out::println);  // Elsa
                                   // Elsa

এখানে limit(2) sort-এর আগেই stream-টাকে finite করে দিয়েছে → Elsa দুইবার প্রিন্ট হয়।

Stream.generate(() -> "Olaf Lazisson")
   .filter(n -> n.length() == 4)
   .limit(2).sorted()
   .forEach(System.out::println);  // hangs

Filter কিছুই পার হতে দেয় না, তাই limit(2) কখনো দুটো element পায় না — pipeline চিরকাল অপেক্ষা করে।

✓ KEY RULE Infinite stream দেখলে দুটো প্রশ্ন করো: (১) sorted()-এর মতো all-elements operation-এর আগে কি limit() আছে? (২) Filter কি আদৌ limit পূরণের মতো element ছাড়বে? দুটোর উত্তর হ্যাঁ না হলে code hang করবে।

Chained pipelines

30: long count = Stream.of("goldfish", "finch")
31:    .filter(s -> s.length() > 5)
32:    .collect(Collectors.toList())
33:    .stream()
34:    .count();
35: System.out.println(count);   // 1

এখানে দুটো pipeline: লাইন 30–32 (source লাইন 30, terminal collect লাইন 32) আর লাইন 33–34 (source লাইন 33, terminal count লাইন 34)। শুধু goldfish (৮ অক্ষর) filter পার হয়, তাই count হয় 1। লম্বা answer option দেখলে option-গুলোর মধ্যে পার্থক্যে ফোকাস করো — উত্তর ওখানেই লুকিয়ে থাকে।

SECTION 07

Primitive Streams নিয়ে কাজ

তিনটা primitive stream interface আছে:

  • IntStream — int, short, byte ও char-এর জন্য
  • LongStream — long-এর জন্য
  • DoubleStream — double ও float-এর জন্য

কেন দরকার? Numeric কাজের জন্য বিল্ট-ইন convenience method:

Stream<Integer> stream = Stream.of(1, 2, 3);
System.out.println(stream.mapToInt(x -> x).sum());  // 6

IntStream intStream = IntStream.of(1, 2, 3);
OptionalDouble avg = intStream.average();
System.out.println(avg.getAsDouble());              // 2.0
★ REMEMBER — case গুরুত্বপূর্ণ Capital-S দিয়ে Stream মানে object-stream interface। ছোট হাতের "stream" মানে concept-টা — Stream, IntStream, LongStream, DoubleStream সবই।

Primitive stream তৈরি করা

DoubleStream empty    = DoubleStream.empty();

DoubleStream varargs  = DoubleStream.of(1.0, 1.1, 1.2);
var random    = DoubleStream.generate(Math::random);   // infinite
var fractions = DoubleStream.iterate(.5, d -> d / 2);  // infinite

range() ও rangeClosed()

IntStream.iterate(1, n -> n + 1).limit(5)
   .forEach(System.out::print);          // 12345 (লম্বা পথ)
IntStream.range(1, 6)
   .forEach(System.out::print);          // 12345 (6 exclusive)
IntStream.rangeClosed(1, 5)
   .forEach(System.out::print);          // 12345 (5 inclusive)
✓ KEY RULE range(a, b): a inclusive, b exclusive। rangeClosed(a, b): দুটোই inclusive। শুধু IntStream ও LongStream-এ আছে — DoubleStream-এ নেই।

Primitive Optional ও Summary Statistics

Primitive streams primitive optional রিটার্ন করে: OptionalDouble, OptionalInt, OptionalLong — এগুলো primitive-এর জন্য; Optional<Double> wrapper class-এর জন্য।

var stream = IntStream.rangeClosed(1, 10);
OptionalDouble optional = stream.average();
optional.ifPresent(System.out::println);                  // 5.5
System.out.println(optional.getAsDouble());               // 5.5
System.out.println(optional.orElseGet(() -> Double.NaN)); // 5.5
OptionalDoubleOptionalIntOptionalLong
Primitive হিসেবে পাওয়াgetAsDouble()getAsInt()getAsLong()
orElseGet()-এর parameterDoubleSupplierIntSupplierLongSupplier

Summary statistics — এক stream থেকে min এবং max

একটা stream-এ terminal operation একটাই — তাই একই stream-এ min() ও max() দুটো কল করা যায় না। summaryStatistics() এক পাসে সব হিসাব করে দেয়:

private static int range(IntStream ints) {
   IntSummaryStatistics stats = ints.summaryStatistics();
   if (stats.getCount() == 0) throw new RuntimeException();
   return stats.getMax() - stats.getMin();
}

Summary statistics-এর getter (empty stream-এর value-গুলো জেনে রাখো!)

  • getCount() → value-সংখ্যা, long।
  • getAverage() → double; empty stream হলে 0.0।
  • getSum() → DoubleSummaryStatistics-এ double; Int/Long-এ long।
  • getMin() → সবচেয়ে ছোট সংখ্যা (double/int/long); empty stream হলে সেই type-এর সবচেয়ে বড় value।
  • getMax() → সবচেয়ে বড় সংখ্যা; empty stream হলে সেই type-এর সবচেয়ে ছোট value।
SECTION 09

Lazy Data Link ও Optional Chaining

Stream underlying data-র সাথে যুক্ত থাকে

25: var cats = new ArrayList<String>();
26: cats.add("Annie");
27: cats.add("Ripley");
28: var stream = cats.stream();
29: cats.add("KC");
30: System.out.println(stream.count());  // 3
⚠ EXAM TRAP উত্তর 3, 2 নয়। লাইন 28-এ stream আসলে তৈরি হয় না — এমন একটা object তৈরি হয় যে জানে দরকারের সময় data কোথায় খুঁজতে হবে। লাইন 29-এ যোগ হওয়া element-টা লাইন 30-এ pipeline চলার সময় দেখা যায়। Lazy evaluation!

Optional chaining

MethodOptional empty হলেOptional-এ value থাকলে
filter(Predicate p)Empty Optional রিটার্ন করেPredicate match করলে element-সহ Optional, নয়তো empty Optional
flatMap(Function f)Empty Optional রিটার্ন করেFunction apply করা Optional; Function-এর return type-কে Optional inherit করতে হবে

private static void threeDigit(Optional<Integer> optional) {
   optional.map(n -> "" + n)           // part 1
      .filter(s -> s.length() == 3)    // part 2
      .ifPresent(System.out::println); // part 3
}
Trace — তিন রকম input:
  • Empty Optional: map() আর filter() খালি বাক্সটাই pass করে দেয়; ifPresent() কিছু করে না।
  • Optional.of(4): map হয়ে "4"; filter fail করে (length 1) → empty Optional; কিছু প্রিন্ট হয় না।
  • Optional.of(123): map হয়ে "123"; filter pass; ifPresent 123 প্রিন্ট করে।
⚠ EXAM TRAP — Optional-এ map বনাম flatMap 
// helper method রিটার্ন করে Optional<Integer>
Optional<Integer> result = optional
   .map(ChainingOptionals::calculator);     // DOES NOT COMPILE
Optional<Integer> result = optional
   .flatMap(ChainingOptionals::calculator); // OK
Map করা method নিজেই Optional<Integer> রিটার্ন করলে map() সেটাকে আবার মোড়ায় → Optional<Optional<Integer>>, যা declared type-এর সাথে মেলে না। flatMap() বাড়তি layer-টা flatten করে দেয়।
★ REMEMBER — checked exception ও functional interface Supplier (অধিকাংশ functional interface-এর মতোই) কোনো checked exception declare করে না। তাই create() method IOException throw করলে Supplier<List<String>> s = ExceptionCaseStudy::create; DOES NOT COMPILE — এমনকি enclosing method-এ throws IOException থাকলেও। সমাধান: lambda-র ভেতরে catch করে unchecked exception হিসেবে rethrow, অথবা একটা safe wrapper method বানিয়ে সেটার reference ব্যবহার।
SECTION 10

Collecting Results — Basic Collectors ও toMap

Predefined collector-গুলো হলো Collectors class-এর static method (Collections-এর মতো helper class) — collect()-এ pass করতে হয়। Collector নিজে নিজে কিছুই করে না।

var ohMy = Stream.of("lions", "tigers", "bears");
String result = ohMy.collect(Collectors.joining(", "));
System.out.println(result); // lions, tigers, bears

Double avg = ohMy2.collect(Collectors.averagingInt(String::length));
System.out.println(avg);    // 5.333333333333333

TreeSet<String> ts = ohMy3.filter(s -> s.startsWith("t"))
   .collect(Collectors.toCollection(TreeSet::new)); // [tigers]
★ REMEMBER Collector-এর averaging method-গুলো wrapper Double রিটার্ন করে (Object দরকার বলে), যেখানে primitive stream-এর average() দেয় OptionalDouble।
⚠ EXAM TRAP — toList() বনাম Collectors.toList() 
List<String> mutableList   = stream1.collect(Collectors.toList());
List<String> immutableList = stream2.toList();
mutableList.add("zebras");   // No issues
immutableList.add("zebras"); // UnsupportedOperationException
Collectors.toList() → mutable list। Shortcut stream.toList() → এমন list যেটায় change করা যায় না।

Map-এ collect করা — toMap()

var ohMy = Stream.of("lions", "tigers", "bears");
Map<String, Integer> map = ohMy.collect(
   Collectors.toMap(s -> s, String::length));
System.out.println(map); // {lions=5, bears=5, tigers=6}

প্রথম function → key; দ্বিতীয় function → value। s -> s-এর জায়গায় Function.identity() লেখা যায়।

⚠ EXAM TRAP — duplicate key 
Map<Integer, String> map = ohMy.collect(Collectors.toMap(
   String::length, k -> k));  // BAD
// java.lang.IllegalStateException: Duplicate key 5
//   (attempted merging values lions and bears)
"lions" আর "bears" — দুটোরই length 5। Merge function না দিলে collector runtime-এ IllegalStateException throw করে (compile কিন্তু দিব্যি হয়!)। 
// সমাধান: merge function (৩য় arg); map type ঠিক করতে supplier (৪র্থ arg)
TreeMap<Integer, String> map = ohMy.collect(Collectors.toMap(
   String::length,
   k -> k,
   (s1, s2) -> s1 + "," + s2,
   TreeMap::new));
System.out.println(map);            // {5=lions,bears, 6=tigers}
System.out.println(map.getClass()); // class java.util.TreeMap
✓ KEY RULE Supplier না দিলে return হওয়া Map ঘটনাচক্রে HashMap হয়, কিন্তু এটা guaranteed নয় — কখনো এর ওপর ভরসা করো না।
SECTION 11

Grouping, Partitioning, Mapping ও Teeing

পরীক্ষা-নির্মাতারা groupingBy() আর partitioningBy() নিয়ে প্রশ্ন করতে ভালোবাসেন।

groupingBy()

var ohMy = Stream.of("lions", "tigers", "bears");
Map<Integer, List<String>> map = ohMy.collect(
   Collectors.groupingBy(String::length));
System.out.println(map); // {5=[lions, bears], 6=[tigers]}

// Downstream collector: value হবে Set
Map<Integer, Set<String>> map2 = ohMy2.collect(
   Collectors.groupingBy(String::length, Collectors.toSet()));

// Map-type supplier + downstream collector
TreeMap<Integer, Set<String>> map3 = ohMy3.collect(
   Collectors.groupingBy(String::length, TreeMap::new, Collectors.toSet()));

// প্রতি group-এ কতটা করে?
Map<Integer, Long> map4 = ohMy4.collect(
   Collectors.groupingBy(String::length, Collectors.counting()));
System.out.println(map4); // {5=2, 6=1}
⚠ EXAM TRAP groupingBy()-তে দেওয়া function null রিটার্ন করতে পারবে না — null key allowed নয়। আরও লক্ষ করো: counting()-এর ফল Long, Integer নয়।

partitioningBy()

Map<Boolean, List<String>> map = ohMy.collect(
   Collectors.partitioningBy(s -> s.length() <= 5));
System.out.println(map); // {false=[tigers], true=[lions, bears]}

Map<Boolean, List<String>> map2 = ohMy2.collect(
   Collectors.partitioningBy(s -> s.length() <= 7));
System.out.println(map2); // {false=[], true=[lions, tigers, bears]}

partitioningBy() — নিয়মগুলো

  • Grouping-এর বিশেষ রূপ — group ঠিক দুটো: true আর false।
  • Map-এ দুটো key-ই সবসময় থাকে — এক পাশের value খালি list হলেও।
  • Downstream collector দিয়ে value-র type বদলানো যায় (যেমন Collectors.toSet())।
  • groupingBy()-এর মতো Map-এর type বদলানো যায় না।
  • Key হলো Boolean (wrapper) — generics-এ primitive boolean চলে না।

groupingBy(Function)

  • Key ঠিক করে তোমার function (যেকোনো type)।
  • Match আছে এমন group-গুলোই কেবল Map-এ আসে।
  • Optional downstream collector এবং Map supplier — দুটোই আছে।
  • Function null রিটার্ন করতে পারবে না।

partitioningBy(Predicate)

  • Key সবসময় true / false।
  • দুটো key-ই সবসময় থাকে, value খালি হতে পারে।
  • Optional downstream collector আছে, কিন্তু Map supplier নেই।
  • Function নয় — Predicate নেয়।

mapping() — collector-এর ভেতরে collector

Map<Integer, Optional<Character>> map = ohMy.collect(
   Collectors.groupingBy(
      String::length,
      Collectors.mapping(
         s -> s.charAt(0),
         Collectors.minBy((a, b) -> a - b))));
System.out.println(map); // {5=Optional[b], 6=Optional[t]}

mapping() দুটো parameter নেয়: value-র function, আর সেটাকে আরও group করার উপায়। Static import সহও দেখতে পারো (groupingBy(…, mapping(…, minBy(…)))) — Collectors. prefix ছাড়াই collector-এর নামগুলো চিনতে হবে।

teeing() — এক পাসে দুটো জিনিস রিটার্ন

record Separations(String spaceSeparated, String commaSeparated) {}

var list = List.of("x", "y", "z");
Separations result = list.stream()
   .collect(Collectors.teeing(
      Collectors.joining(" "),
      Collectors.joining(","),
      (s, c) -> new Separations(s, c)));
System.out.println(result);
// Separations[spaceSeparated=x y z, commaSeparated=x,y,z]
✓ KEY RULE teeing(c1, c2, biFunction) stream-টা দুটো collector-কে খাওয়ায়, তারপর দুই result মিলিয়ে একটাই object বানায় — এক পাস, এক return value।

SECTION 12

Spliterator ব্যবহার

Spliterator ভাবো এমন একটা ব্যাগ যেটা ভাগ করা যায়: trySplit() ব্যাগ থেকে মোটামুটি অর্ধেক data বের করে নতুন একটা Spliterator-এ দেয়; বাকিটা original-এই থাকে। নিজে Spliterator implement করা পরীক্ষায় নেই — এই তিনটা method ব্যবহার করাটা আছে:

Methodকাজ
Spliterator<T> trySplit()আদর্শভাবে অর্ধেক data-সহ একটা Spliterator দেয়, যা current টা থেকে সরে যায়। বারবার কল করা যায়; আর ভাগ করা না গেলে একসময় null দেয়।
void forEachRemaining(Consumer<T> c)বাকি সব element process করে।
boolean tryAdvance(Consumer<T> c)একটা element process করে (থাকলে); element process হলো কি না সেটা রিটার্ন করে।
12: var stream = List.of("bird-", "bunny-", "cat-", "dog-", "fish-", "lamb-",
13:    "mouse-");
14: Spliterator<String> originalBagOfFood = stream.spliterator();
15: Spliterator<String> emmasBag = originalBagOfFood.trySplit();
16: emmasBag.forEachRemaining(System.out::print);  // bird-bunny-cat-
18: Spliterator<String> jillsBag = originalBagOfFood.trySplit();
19: jillsBag.tryAdvance(System.out::print);        // dog-
20: jillsBag.forEachRemaining(System.out::print);  // fish-
22: originalBagOfFood.forEachRemaining(System.out::print); // lamb-mouse-
Trace:
  • শুরুতে ৭টা element। trySplit() → Emma পায় সামনের ~অর্ধেক: bird-, bunny-, cat- (৩টা)।
  • Original-এ থাকে ৪টা। দ্বিতীয় trySplit() → Jill পায় dog-, fish- (২টা)।
  • tryAdvance একটা প্রিন্ট করে (dog-); forEachRemaining Jill-এর ব্যাগের বাকিটা (fish-)।
  • Original-এ থাকে lamb-, mouse- → শেষে সেগুলো প্রিন্ট হয়।
var originalBag = Stream.iterate(1, n -> ++n).spliterator();
Spliterator<Integer> newBag = originalBag.trySplit();
newBag.tryAdvance(System.out::print); // 1
newBag.tryAdvance(System.out::print); // 2
newBag.tryAdvance(System.out::print); // 3
✓ KEY RULE Infinite stream-এও trySplit() দিব্যি কাজ করে — Spliterator "অর্ধেক" নেওয়ার চেষ্টা করে না; বরং অনেকগুলো element-ওয়ালা একটা ব্যাগ দেয়। তবে infinite Spliterator-এ forEachRemaining() কল করা খুবই খারাপ বুদ্ধি। Stream-backed Spliterator lazily evaluate হয়; CONCURRENT, ORDERED, SIZED, SORTED-এর মতো characteristics আছে, কিন্তু পরীক্ষায় শুধু সোজাসাপ্টা Spliterator-ই আসবে।

★ সংক্ষিপ্ত রিভিউ

Optional

  • Factory: empty(), of(), ofNullable(); public constructor নেই। Empty-তে get() → NoSuchElementException।
  • orElse(value) / orElseGet(value-র Supplier) / orElseThrow(no-arg বা exception-এর Supplier)।

Pipeline

  • Source + শূন্য-বা-একাধিক intermediate op + ঠিক একটা terminal op; lazy evaluation; stream একবারই ব্যবহারযোগ্য।

Terminal operations

  • Reduction: count, min, max, reduce, collect। Reduction নয়: find/match/forEach। Infinite stream-এ কেবল find (সবসময়) আর match (কখনো কখনো) শেষ হতে পারে।

Intermediate operations

  • filter, distinct, limit/skip, map, flatMap, sorted, peek। sorted()-এর সব element লাগে — infinite stream-এ আগে limit() দাও।

Primitive streams

  • IntStream (int/short/byte/char), LongStream, DoubleStream; range (end exclusive) বনাম rangeClosed (end inclusive); mapToX/mapToObj/boxed; sum() → primitive (empty হলে 0), average() → সবসময় OptionalDouble।

Collectors

  • toMap-এ merge ছাড়া duplicate key → IllegalStateException। groupingBy: null key নয়, Map supplier আছে। partitioningBy: সবসময় দুটো Boolean key, Map supplier নেই। teeing: দুই collector + merger। stream.toList() unmodifiable; Collectors.toList() mutable।

Spliterator

  • trySplit() ~অর্ধেক সরিয়ে নেয়; tryAdvance() একটা element (boolean রিটার্ন); forEachRemaining() বাকি সব।

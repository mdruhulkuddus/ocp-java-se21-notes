Q1Optional

What is the result of the following?

Optional<Double> opt = Optional.empty();
System.out.println(opt.get());
A.It prints null
B.It prints Optional.empty
C.A NoSuchElementException is thrown at runtime
D.The code does not compile
Show Answer
C · NoSuchElementException

Calling get() on an empty Optional throws java.util.NoSuchElementException: No value present. The code compiles fine (A/D wrong), and Optional never hands you null from get().

Q2Optional

Given Optional<Double> opt, which is true of this statement?

System.out.println(opt.orElseGet(
   () -> new IllegalStateException()));
A.It throws IllegalStateException if opt is empty
B.It prints the exception's toString if opt is empty
C.It does not compile
D.It prints the value if present, otherwise nothing
Show Answer
C · Does not compile

orElseGet() takes a Supplier that must return the Optional's type — a Double here. A Supplier returning an IllegalStateException is a type mismatch. To throw, use orElseThrow(Supplier) instead.

Q3Optional

What does the following print, given average(90, 100) returns Optional.of(95.0)?

Optional<Double> opt = average(90, 100);
System.out.println(opt.orElse(Double.NaN));
System.out.println(opt.orElseGet(() -> Math.random()));
System.out.println(opt.orElseThrow());
A.NaN, a random number, then an exception
B.95.0 three times
C.95.0 twice, then NoSuchElementException
D.The code does not compile
Show Answer
B · 95.0 three times

A value is present, so all three "or else" methods simply return it — the fallback logic never runs. A describes empty-Optional behavior.

Q4Sources

What is the result of the following?

Stream<Integer> s = Stream.iterate(1; n -> n < 50; n -> n + 2);
System.out.println(s.count());
A.25
B.50
C.The code does not compile
D.The code hangs
Show Answer
C · Does not compile

The three-argument iterate() is a regular method call — its parameters are separated by commas, not semicolons. The semicolons make it look like a for loop, which is exactly the trick the exam plays.

Q5Pipeline

Which are true statements about terminal operations in a stream pipeline that runs successfully? (Choose all that apply.)

A.At most one terminal operation can exist in a stream pipeline
B.Terminal operations are a required part of the pipeline in order to get a result
C.Terminal operations have Stream as their return type
D.peek() is an example of a terminal operation
E.The stream may be used again after calling a terminal operation
Show Answer
A, B

A pipeline has exactly one terminal operation, and without it no result is produced (intermediate ops never even run). C is wrong — returning a stream type is the mark of an intermediate operation. D is wrong — peek() is intermediate. E is wrong — a stream is invalid after its terminal operation.

Q6Terminal Ops

What is the result of the following?

Stream<String> s = Stream.generate(() -> "chimp");
System.out.println(s.count());
A.0
B.1
C.The code does not compile
D.The code hangs
Show Answer
D · Hangs

count() is a reduction — it must look at every element, and an infinite stream never runs out. Same fate awaits min(), max(), forEach(), reduce(), and collect() on infinite streams.

Q7Terminal Ops

What does the following print?

Optional<?> minEmpty = Stream.empty().min((s1, s2) -> 0);
System.out.println(minEmpty.isPresent());
A.true
B.false
C.A NoSuchElementException is thrown
D.The code does not compile
Show Answer
B · false

The stream is empty, so the comparator is never called and min() returns an empty Optional. isPresent() on an empty Optional is false — no exception, because we never called get().

Q8Terminal Ops

What is the output of the following?

var list = List.of("monkey", "2", "chimp");
Predicate<String> pred = x -> Character.isLetter(x.charAt(0));
System.out.print(list.stream().anyMatch(pred) + " ");
System.out.print(list.stream().allMatch(pred) + " ");
System.out.print(list.stream().noneMatch(pred));
A.true true false
B.true false false
C.true false true
D.An exception is thrown — the stream is reused
Show Answer
B · true false false

Two of three elements start with a letter → anyMatch true; "2" fails → allMatch false; at least one matches → noneMatch false. No reuse problem: each call creates a new stream from the list (D wrong).

Q9Terminal Ops

What is the result of the following?

Stream<String> infinite = Stream.generate(() -> "chimp");
Predicate<String> pred = x -> Character.isLetter(x.charAt(0));
System.out.println(infinite.allMatch(pred));
A.true
B.false
C.The code does not compile
D.The code never terminates
Show Answer
D · Never terminates

Every generated element matches, so allMatch() can never prove or disprove the claim without checking them all — and there are infinitely many. Had one element failed the predicate, it would have returned false and stopped.

Q10Terminal Ops

What is the result of the following?

Stream<Integer> s = Stream.of(1);
for (Integer i : s) {
   System.out.println(i);
}
A.1
B.Nothing is printed
C.The code does not compile
D.An exception is thrown at runtime
Show Answer
C · Does not compile

A for-each loop requires the source to implement Iterable — streams don't. Use forEach() instead; despite the name similarity, it is a terminal operation, not a loop.

Q11Terminal Ops

What does the following print?

Stream<Integer> stream = Stream.of(3, 5, 6);
System.out.println(stream.reduce(1, (a, b) -> a * b));
A.14
B.90
C.Optional[90]
D.The code does not compile
Show Answer
B · 90

Identity 1, accumulator multiplication: 1×3×5×6 = 90. Because an identity is supplied, the return type is T (Integer), not Optional<T> — so C is wrong.

Q12Terminal Ops

What does the following print?

Stream<String> stream = Stream.of("w", "o", "l", "f!");
int length = stream.reduce(0, (i, s) -> i + s.length(), (a, b) -> a + b);
System.out.println(length);
A.4
B.5
C.0
D.The code does not compile — the accumulator mixes types
Show Answer
B · 5

The three-arg reduce() exists precisely to mix types: the accumulator combines an Integer running total with each String. Lengths 1+1+1+2 = 5. The combiner merges partial totals (used with parallel streams).

Q13Collect

What does the following print?

Stream<String> stream = Stream.of("w", "o", "l", "f");
TreeSet<String> set = stream.collect(
   TreeSet::new, TreeSet::add, TreeSet::addAll);
System.out.println(set);
A.[w, o, l, f]
B.[f, l, o, w]
C.wolf
D.The code does not compile
Show Answer
B · [f, l, o, w]

This is the supplier/accumulator/combiner form of collect(). A TreeSet keeps natural sorted order, so the letters come out alphabetically, not in insertion order (A wrong).

Q14Intermediate Ops

What does the following print?

Stream<Integer> s = Stream.iterate(1, n -> n + 1);
s.skip(5)
 .limit(2)
 .forEach(System.out::print);
A.12
B.56
C.67
D.The code hangs
Show Answer
C · 67

The infinite stream counts 1, 2, 3, …; skip(5) drops 1–5 so it now starts at 6; limit(2) makes it finite with elements 6 and 7. It doesn't hang because limit() tells the foreperson to stop the line.

Q15Intermediate Ops

What does the following print?

Stream<String> s = Stream.of("monkey", "gorilla", "bonobo");
s.map(String::length)
 .forEach(System.out::print);
A.667
B.676
C.monkeygorillabonobo
D.The code does not compile
Show Answer
B · 676

String::length is shorthand for x -> x.length(): monkey=6, gorilla=7, bonobo=6 → 676. Watch the element order — A reverses two of the lengths.

Q16Intermediate Ops

Which is true of the following?

List<Integer> x1 = List.of(1, 2, 3);
List<Integer> x2 = List.of(4, 5, 6);
List<Integer> x3 = List.of();
Stream.of(x1, x2, x3).map(x -> x + 1)
   .flatMap(x -> x.stream())
   .forEach(System.out::print);
A.It prints 123456
B.It prints 234567
C.It prints nothing
D.The code does not compile
Show Answer
D · Does not compile

Inside map(), each element x is a List<Integer>, not an Integer — and you can't add 1 to a List. Had the map() call been removed, flatMap would flatten the lists and print 123456.

Q17Intermediate Ops

What is the result of the following?

Stream<String> s = Stream.of("brown bear-", "grizzly-");
s.sorted(Comparator::reverseOrder)
 .forEach(System.out::print);
A.grizzly-brown bear-
B.brown bear-grizzly-
C.The code does not compile
D.An exception is thrown at runtime
Show Answer
C · Does not compile

Comparator::reverseOrder references a method taking no arguments and returning a Comparator — equivalent to a Supplier<Comparator>, which is not a Comparator. With Comparator.reverseOrder() (a method call), the output would be A.

Q18Pipeline

What is the result of the following?

Stream.generate(() -> "Elsa")
   .filter(n -> n.length() == 4)
   .sorted()
   .limit(2)
   .forEach(System.out::println);
A.It prints Elsa twice
B.It prints Elsa once
C.It hangs (or eventually runs out of memory)
D.The code does not compile
Show Answer
C · Hangs

sorted() sits before limit(), and it can't emit anything until it has seen every element — which never happens on an infinite stream. Compare with Q19.

Q19Pipeline

What is the result of the following?

Stream.generate(() -> "Elsa")
   .filter(n -> n.length() == 4)
   .limit(2)
   .sorted()
   .forEach(System.out::println);
A.It prints Elsa twice
B.It prints Elsa once
C.It hangs
D.The code does not compile
Show Answer
A · Elsa twice

Now limit(2) comes first, making the stream finite before sorted() runs. Two "Elsa" strings pass the filter, get sorted (trivially), and print. If the generated string were "Olaf Lazisson", the filter would pass nothing, limit(2) would never fill, and the code would hang.

Q20Intermediate Ops

What does the following print?

var numbers = new ArrayList<>();
var letters = new ArrayList<>();
numbers.add(1);
letters.add('a');
Stream<List<?>> bad = Stream.of(numbers, letters);
bad.peek(x -> x.remove(0))
   .map(List::size)
   .forEach(System.out::print);
A.11
B.00
C.The code does not compile
D.A ConcurrentModificationException is thrown
Show Answer
B · 00

Java doesn't stop peek() from mutating the data — each list loses its only element before map(List::size) runs, so both sizes are 0. Without the peek, the output would be 11. Bad practice, valid Java.

Q21Pipeline

What does the following print?

long count = Stream.of("goldfish", "finch")
   .filter(s -> s.length() > 5)
   .collect(Collectors.toList())
   .stream()
   .count();
System.out.println(count);
A.0
B.1
C.2
D.An IllegalStateException — the stream is reused
Show Answer
B · 1

These are two chained pipelines, not one reused stream: pipeline 1 ends at collect(), and .stream() starts a brand-new pipeline from the collected list. Only goldfish (8 chars) beats the length-5 filter; finch has exactly 5 and > 5 is strict.

Q22Primitive Streams

Which of the following print exactly 12345? (Choose all that apply.)

A.IntStream.range(1, 5).forEach(System.out::print);
B.IntStream.range(1, 6).forEach(System.out::print);
C.IntStream.rangeClosed(1, 5).forEach(System.out::print);
D.IntStream.rangeClosed(1, 6).forEach(System.out::print);
Show Answer
B, C

range() is inclusive-exclusive, so B gives 1–5; rangeClosed() is inclusive-inclusive, so C gives 1–5 too. A prints 1234 and D prints 123456.

Q23Primitive Streams

Which is true of the following?

4: Stream<Integer> s = Stream.of(1);
5: IntStream is = s.boxed();
A.The code compiles and is contains one element
B.Line 5 does not compile
C.Line 4 does not compile
D.The code compiles but throws an exception at runtime
Show Answer
B · Line 5 does not compile

boxed() exists only on the primitive streams (IntStream, LongStream, DoubleStream) to convert toward objects — a Stream<Integer> has no such method, and its result would be a Stream anyway, not an IntStream. To go object→primitive, use mapToInt().

Q24Primitive Streams

Given var is = IntStream.empty(); which are true? (Choose all that apply.)

A.is.average() returns the type OptionalDouble
B.is.average() returns the type OptionalInt
C.is.sum() returns the type int, with value 0
D.is.sum() returns the type OptionalInt
E.is.findAny() returns the type OptionalInt

A, C, E

average() always returns OptionalDouble regardless of stream type (averages can be fractional). sum() returns the primitive — an empty stream sums to 0, no Optional involved. Element-returning methods like findAny() on an IntStream use OptionalInt.

var cats = new ArrayList<String>();

Q26Optional

Given the method below, what prints when it is called with Optional.of(4)?

private static void threeDigit(Optional<Integer> optional) {
   optional.map(n -> "" + n)
      .filter(s -> s.length() == 3)
      .ifPresent(System.out::println);
}
A.4
B.004
C.Nothing is printed
D.A NoSuchElementException is thrown
Show Answer
C · Nothing

4 is mapped to the String "4", whose length is 1, so filter() returns an empty Optional and ifPresent() silently does nothing. With Optional.of(123) it would print 123; with an empty Optional, still nothing — no exception either way.

Q27Optional

The helper below returns Optional<Integer>. Which assignment compiles?

public static Optional<Integer> calculator(String text) { … }

Optional<String> optional = Optional.of("95");
// which line?
A.Optional<Integer> r = optional.map(ChainingOptionals::calculator);
B.Optional<Integer> r = optional.flatMap(ChainingOptionals::calculator);
C.Both A and B
D.Neither A nor B
Show Answer
B · flatMap

map() wraps the method's result in another Optional, producing Optional<Optional<Integer>> — a type mismatch, so A does not compile. flatMap() flattens that extra layer, which is exactly its job when chaining Optional-returning methods.

Q28Collectors

What is the result of the following?

var ohMy = Stream.of("lions", "tigers", "bears");
Map<Integer, String> map = ohMy.collect(
   Collectors.toMap(String::length, k -> k));
System.out.println(map);
A.{5=lions, 6=tigers}
B.{5=bears, 6=tigers}
C.{5=lions,bears, 6=tigers}
D.The code compiles but throws an IllegalStateException at runtime
Show Answer
D · IllegalStateException

"lions" and "bears" both map to key 5, and without a merge function the collector refuses to choose: Duplicate key 5 (attempted merging values lions and bears). Adding a third argument like (s1, s2) -> s1 + "," + s2 produces C.

Q29Collectors

Which are true about partitioningBy()? (Choose all that apply.)

var ohMy = Stream.of("lions", "tigers", "bears");
Map<Boolean, List<String>> map = ohMy.collect(
   Collectors.partitioningBy(s -> s.length() <= 7));
System.out.println(map);
A.The output is {true=[lions, tigers, bears]}
B.The output is {false=[], true=[lions, tigers, bears]}
C.A downstream collector could change the values to a Set
D.A map supplier such as TreeMap::new could change the Map type, like groupingBy()
Show Answer
B, C

A partitioned map always has both keys, even when one holds an empty list — so B, not A. A downstream collector (e.g. Collectors.toSet()) may change the value type (C). But unlike groupingBy(), partitioningBy() has no overload accepting a Map supplier (D wrong).

Q30Collectors · Spliterator

What does the following print?

var list = List.of("bird-", "bunny-", "cat-", "dog-", "fish-", "lamb-", "mouse-");
Spliterator<String> original = list.spliterator();
Spliterator<String> emmasBag = original.trySplit();
emmasBag.forEachRemaining(System.out::print);
A.bird-bunny-cat-
B.dog-fish-lamb-mouse-
C.bird-bunny-cat-dog-fish-lamb-mouse-
D.Nothing — trySplit() returns an empty Spliterator
Show Answer
A · bird-bunny-cat-

trySplit() removes roughly the front half of the seven elements into the new Spliterator — bird-, bunny-, cat-. The original keeps the remaining four (dog- onward). Bonus rule: tryAdvance() processes one element and returns a boolean; trySplit() even works on infinite streams (it just won't take "half").

★ Quick Revision — Chapter 10 Core Traps

  • Optional: get()/orElseThrow() on empty → NoSuchElementException; orElseGet Supplier must return the value's type, never an exception.
  • Pipeline: one terminal op per stream; stream dead afterwards; intermediate ops are lazy; streams are not Iterable (no for-each).
  • Infinite streams: find methods terminate; match methods sometimes; count/min/max/forEach/reduce/collect hang. sorted() before limit() hangs; a filter that passes nothing before limit() hangs.
  • Method references: Comparator::reverseOrder is a Supplier, not a Comparator — compile error in sorted().
  • Lazy link: elements added to the source List before the terminal op runs are included.
  • Primitive streams: range end-exclusive / rangeClosed end-inclusive; boxed() only on primitive streams; sum() → primitive (0 when empty); average() → always OptionalDouble.
  • Optional chaining: a method that already returns Optional needs flatMap, not map.
  • Collectors: toMap with duplicate keys and no merge function → IllegalStateException; groupingBy forbids null keys and accepts a Map supplier; partitioningBy always yields both Boolean keys and accepts no Map supplier; stream.toList() is unmodifiable while Collectors.toList() is mutable.
  • Spliterator: trySplit() removes ~the front half; tryAdvance() one element (boolean); forEachRemaining() the rest — never on an infinite Spliterator.

Section 01

Referencing Files and Directories

Conceptualizing the file system

A file within a storage device holds data. Files are organized into hierarchies using directories — a location that can contain files as well as other directories. In Java we often treat directories like files, using many of the same classes and methods; in this chapter "file" often means "file or directory."

The file system is in charge of reading and writing data within a computer; the JVM automatically connects to the local one. The root directory is the topmost directory — C:\ on Windows, / on Linux. A path is a representation of a file or directory; the value to the left of a separator is the parent of the value to the right.

Absolute vs. relative — the exam's conventions

  • If a path starts with a forward slash (/), it is absolute, with / as the root — e.g. /bird/parrot.png.
  • If a path starts with a drive letter (C:), it is absolute, with the drive letter as the root — e.g. C:/bird/info.
  • Otherwise, it is a relative path — e.g. bird/parrot.png.
SymbolDescription
.A reference to the current directory
..A reference to the parent of the current directory

With a current directory of /fish/shark/hammerhead, ../swim.txt is equivalent to /fish/shark/swim.txt, and ../../clownfish is equivalent to /fish/clownfish. Redundancies like /fish/clownfish/../shark/./swim.txt can be simplified with normalize().

A symbolic link is a special file that serves as a pointer to another file or directory. With a link from /zoo/user/favorite to /fish/shark, both /fish/shark/swim.txt and /zoo/user/favorite/swim.txt reference the same file.

✓ Key Rule

The legacy I/O APIs do not support symbolic links. NIO.2 includes full support for creating, detecting, and navigating them.

Creating a File

File zooFile1 = new File("/home/tiger/data/stripes.txt");
File zooFile2 = new File("/home/tiger", "data/stripes.txt");

File parent = new File("/home/tiger");
File zooFile3 = new File(parent, "data/stripes.txt");

System.out.println(zooFile1.exists());

All three point to the same location. If null is passed as the parent to the last constructor, it is ignored and the method behaves like the single-String constructor.

⚠ Exam Trap

There is no three-parameter File constructor — new File("/weather", "winter", "snow.dat") does not compile. There is a (File, String) constructor but no (String, File) constructor.

Creating a Path

Path is an interface, so it has no constructors. The usual factory method is:

public static Path of(String first, String... more)
Path zooPath1 = Path.of("/home/tiger/data/stripes.txt");
Path zooPath2 = Path.of("/home", "tiger", "data", "stripes.txt");

System.out.println(Files.exists(zooPath1));

The varargs values are combined and automatically separated by the OS-dependent file separator.

Four ways to obtain a Path

  • Path.of("/home", "tiger", "data") — the preferred factory method.
  • Paths.get("/home", "tiger", "data") — the older Paths helper class; same signature, but may be deprecated in the future.
  • FileSystems.getDefault().getPath("/home/tiger/data/stripes.txt") — what Path.of() uses behind the scenes.
  • Path.of(URI.create("https://www.selikoff.net")) — from a URI, with a scheme such as file:// or https://.
⚠ Exam Trap

new Path("jaguar.txt") does not compile — Path is an interface. And the static method on Path is of(), not get(); get() belongs to Paths. Swapping those two names is the classic distractor.

Switching between File and Path

File file = new File("rabbit");
Path newPath = file.toPath();
File backToFile = newPath.toFile();

Many older libraries use File. For newer applications, rely on NIO.2's Path, which has far more features.

Path is immutable

Path p = Path.of("whale");
p.resolve("krill");
System.out.println(p);   // whale — the result was discarded
⚠ Exam Trap

Like String, Path is immutable. Any line that calls a Path method without assigning the result is effectively a no-op. The exam loves burying p1.normalize().relativize(x); on its own line and then printing p1 unchanged.

Viewing and slicing the path

Path path = Path.of("/land/hippo/harry.happy");
System.out.println("The Path is: " + path);
for(int i=0; i<path.getNameCount(); i++)
   System.out.println("   Element " + i + " is: " + path.getName(i));
The Path is: /land/hippo/harry.happy
   Element 0 is: land
   Element 1 is: hippo
   Element 2 is: harry.happy
  • toString() is the only method in Path that returns a String; most others return Path.
  • getNameCount() and getName() do not include the root, even for an absolute path.
  • Path.of("/").getNameCount() is 0, and getName(0) on it throws IllegalArgumentException.
var p = Path.of("/mammal/omnivore/raccoon.image");
p.subpath(0, 3);   // mammal/omnivore/raccoon.image
p.subpath(1, 2);   // omnivore
p.subpath(1, 3);   // omnivore/raccoon.image

p.subpath(0, 4);   // IllegalArgumentException — max index is 3
p.subpath(1, 1);   // IllegalArgumentException — empty path

subpath() takes an inclusive beginIndex and an exclusive endIndex, is zero-indexed, and excludes the root — and it returns a relative path even when applied to an absolute one.

resolve() — concatenation

Path path1 = Path.of("/cats/../panther");
Path path2 = Path.of("food");
System.out.println(path1.resolve(path2));    // /cats/../panther/food

Path path3 = Path.of("/turkey/food");
System.out.println(path3.resolve("/tiger/cage"));   // /tiger/cage
✓ Key Rule

When you see resolve(), think concatenation. It does not clean up path symbols. And if the argument is an absolute path, that argument is simply returned — you cannot combine two absolute paths with resolve().

relativize() — the path from one to another

var path1 = Path.of("fish.txt");
var path2 = Path.of("friendly/birds.txt");
System.out.println(path1.relativize(path2));   // ../friendly/birds.txt
System.out.println(path2.relativize(path1));   // ../../fish.txt
⚠ Exam Trap

relativize() requires both paths to be both absolute or both relative; mixing them throws IllegalArgumentException. On Windows, two absolute paths must also share the same root/drive letter, or it throws too.

Path.of("/primate/chimpanzee").relativize(Path.of("bananas.txt"));
   // IllegalArgumentException

normalize() and toRealPath()

Path.of("./armadillo/../shells.txt").normalize();   // shells.txt
Path.of("/cats/../panther/food").normalize();      // /panther/food
Path.of("../../fish.txt").normalize();             // ../../fish.txt (unchanged)

var p1 = Path.of("/pony/../weather.txt");
var p2 = Path.of("/weather.txt");
p1.equals(p2);                                 // false
p1.normalize().equals(p2.normalize());         // true

normalize() removes only the redundancies it can reduce — its primary purpose is letting you compare equivalent paths.

Creating, copying, moving, deleting

createDirectory()

  • Throws if the directory already exists
  • Throws if the parent directories do not exist

createDirectories()

  • Creates the target and any missing parents
  • If everything already exists, it completes without doing anything — no exception
Files.copy(Path.of("/panda/bamboo.txt"), Path.of("/panda-save/bamboo.txt"));
Files.copy(Path.of("/turtle"), Path.of("/turtleCopy"));   // SHALLOW copy

Files.copy(Path.of("book.txt"), Path.of("movie.txt"),
   StandardCopyOption.REPLACE_EXISTING);
  • When directories are copied, the copy is shallow — files and subdirectories inside are not copied. A deep copy requires recursion.
  • Without REPLACE_EXISTING, copy() throws if the target already exists.
  • Two overloads work with I/O streams: copy(InputStream in, Path target, CopyOption... o) and copy(Path source, OutputStream out).
⚠ Exam Trap

Copying a file "into" a directory does not do what you expect:

var file = Path.of("food.txt");
var directory = Path.of("/enclosure");   // both exist
Files.copy(file, directory);              // throws at runtime

The command tries to create a new file named /enclosure, and since that path already exists, it throws. If /enclosure did not exist, it would create a file called /enclosure holding the contents of food.txt. The correct target is /enclosure/food.txt. This applies to move() too.

Files.move(Path.of("C:\\zoo"), Path.of("C:\\zoo-new"));
Files.move(Path.of("mouse.txt"), Path.of("gerbil.txt"),
   StandardCopyOption.ATOMIC_MOVE);

An atomic move is a single indivisible operation — any process monitoring the file system never sees an incomplete or partially written file. If the file system does not support it, AtomicMoveNotSupportedException is thrown. Note that although ATOMIC_MOVE is a StandardCopyOption, it will likely throw if passed to copy().

delete(Path)

  • Returns void
  • Throws (NoSuchFileException) if the path does not exist

deleteIfExists(Path)

  • Returns boolean — true if deleted, false otherwise
  • Does not throw when the path is simply missing

Both throw when operated on a nonempty directory — to delete a directory it must be empty. If the path is a symbolic link, the link is deleted, not its target. Both declare IOException.

isSameFile() and mismatch()

Files.isSameFile(Path.of("/animals/cobra"), Path.of("/animals/snake"));
   // true — snake is a symbolic link to cobra

Files.mismatch(Path.of("/animals/monkey.txt"), Path.of("/animals/wolf.txt"));
   // 1 — "Harold" vs "Howler" first differ at index 1
  • isSameFile() resolves all path symbols and follows symbolic links — equals() does neither.
  • Special case: if the two paths are equal per equals(), isSameFile() returns true without checking whether the file exists.
  • mismatch() compares contents: it returns -1 if the files are the same, otherwise the index of the first differing position.
  • mismatch() is symmetric — swapping the arguments gives the same result.
Section 03

Introducing I/O Streams

An I/O stream is a list of data elements presented sequentially — conceptually a nearly never-ending stream of water, read one wave at a time. Because you only hold a small portion at a time, a 1 TB file can be processed by a program with very little memory.

★ Remember

"I/O streams" here are the ones in java.io. When the book says just "streams," it means the Stream API from Chapter 10. The naming overlap is a deliberate exam trap.

Three axes for classifying every I/O stream class

  • Byte vs. character: byte streams read/write binary data and end in InputStream/OutputStream; character streams read/write text and end in Reader/Writer.
  • Input vs. output: most InputStream classes have a matching OutputStream, and most Reader classes a matching Writer.
  • Low-level vs. high-level: a low-level stream connects directly to the data source; a high-level stream is built on top of another stream by wrapping.
✓ Key Rule

Even though character streams don't have "Stream" in their names, they are still I/O streams. And for the exam, the only low-level stream classes you need to know are the ones that operate on files — every other non-abstract stream class is high-level.

Wrapping

try (var br = new BufferedReader(new FileReader("zoo-data.txt"))) {
   System.out.println(br.readLine());
}

try (var ois = new ObjectInputStream(
         new BufferedInputStream(
            new FileInputStream("zoo-data.ser")))) {
   System.out.print(ois.readObject());
}

High-level streams can wrap other high-level streams. Here the low-level FileInputStream interacts with the file, a BufferedInputStream improves performance, and an ObjectInputStream interprets the data as a Java object.

⚠ Exam Trap

Mismatched wrapping is the single most common compile trap in this chapter:

new BufferedInputStream(new FileReader("z.txt"));     // DOES NOT COMPILE
new BufferedWriter(new FileOutputStream("z.txt"));    // DOES NOT COMPILE
new ObjectInputStream(new FileOutputStream("z.txt"));  // DOES NOT COMPILE
new BufferedInputStream(new InputStream());          // DOES NOT COMPILE

The first two mix Reader/Writer with InputStream/OutputStream. The third mixes an OutputStream into an input stream. The fourth fails because InputStream is abstract.

★ Remember

The exceptions to the pairing rules: InputStreamReader is a Reader that takes an InputStream, and OutputStreamWriter is a Writer that takes an OutputStream — the only classes with both naming halves. PrintWriter can take either an OutputStream or a Writer. There is no PrintReader, and PrintStream is an OutputStream that lacks "Output" in its name.

Section 04

Reading and Writing Files

The low-level way

void copyStream(InputStream in, OutputStream out) throws IOException {
   int b;
   while ((b = in.read()) != -1) {
      out.write(b);
   }
}
✓ Key Rule

read() returns int, not byte, because byte has no spare value left to signal the end of the stream. -1 indicates the end of the stream. Output streams use int too, for consistency.

10: void copyStream(InputStream in, OutputStream out) throws IOException {
11:    int batchSize = 1024;
12:    var buffer = new byte[batchSize];
13:    int lengthRead;
14:    while ((lengthRead = in.read(buffer, 0, batchSize)) > 0) {
15:       out.write(buffer, 0, lengthRead);
16:       out.flush();
17:    }
18: }
  • The offset and length apply to the array: offset 3, length 5 means read up to five values into the array starting at position 3.
  • The return value lengthRead is critical. Ignoring it and always writing the full buffer would append leftover bytes from the previous iteration.
  • flush() requests that accumulated data be written to disk immediately. It has a cost, so use it only intermittently — not after every write.
⚠ Exam Trap

Code like while(reader.read(buffer) != -1) { writer.write(buffer); } compiles but is wrong: it ignores how many characters were actually read, so it only copies correctly when the file length is an exact multiple of the buffer size. Otherwise the final write duplicates leftover characters.

The high-level way

26: void copyTextFile(File src, File dest) throws IOException {
27:    try (var reader = new BufferedReader(new FileReader(src));
28:       var writer = new BufferedWriter(new FileWriter(dest))) {
29:       String line = null;
30:       while ((line = reader.readLine()) != null) {
31:          writer.write(line);
32:          writer.newLine();
33:       } } }
  • If the source does not exist, a FileNotFoundException (which inherits IOException) is thrown.
  • If the destination exists, it is overwritten. Pass an optional boolean second parameter to FileWriter to append instead.
  • readLine() strips line breaks, so newLine() puts them back.
  • The try-with-resources closes every object in the chain.

For byte data you would instead pick BufferedInputStream, BufferedOutputStream, FileInputStream, and FileOutputStream, calling readAllBytes() rather than readLine() and storing the result in a byte[].

PrintStream and PrintWriter

try (var reader = new BufferedReader(new FileReader(src));
   var writer = new PrintWriter(new FileWriter(dest))) {
   String line = null;
   while ((line = reader.readLine()) != null)
      writer.println(line);
}

The four key methods are print(), println(), format(), and printf().

✓ Key Rule

The print stream classes' methods do not throw checked exceptions — otherwise you'd have to catch one every time you called System.out.print(). They report problems via checkError() and otherwise fail silently. System.out and System.err are PrintStream objects; System.in is an InputStream.

The line separator is \n or \r\n depending on the OS; println() handles it. To get it directly, use System.lineSeparator() or System.getProperty("line.separator").

Enhancing with Files

String string = Files.readString(input);        Files.writeString(output, string);
byte[] bytes = Files.readAllBytes(input);       Files.write(output, bytes);
List<String> lines = Files.readAllLines(input); Files.write(output, lines);

All three read the entire file at once, storing all contents in memory — a large file may trigger an OutOfMemoryError. The lazy alternative:

try (Stream<String> s = Files.lines(path)) {
   s.filter(f -> f.startsWith("WARN:"))
      .map(f -> f.substring(5))
      .forEach(System.out::println);
}
⚠ Exam Trap

readAllLines() returns a List; lines() returns a Stream. So Stream API methods are not available on the result of readAllLines():

Files.readAllLines(Path.of("birds.txt"))
   .filter(s -> s.length() > 2)      // DOES NOT COMPILE
   .forEach(System.out::println);

forEach() works on both (a List is an Iterable), but filter(), map(), and flatMap() are Stream-only.

✓ Key Rule

NIO.2 stream-based methods (Files.list(), Files.lines(), Files.walk(), Files.find()) open a connection to the file system that must be closed with try-with-resources; a terminal operation does not close them. Streams from Chapter 10 need no closing.

try (var reader = Files.newBufferedReader(input);
     var writer = Files.newBufferedWriter(output)) {
   String line = null;
   while ((line = reader.readLine()) != null) {
      writer.write(line);
      writer.newLine();
   } }

Section 05

Serializing Data

Serialization is the process of converting an in-memory object to a byte stream; deserialization is converting from a byte stream back into an object.

The Serializable interface

java.io.Serializable is a marker interface — it has no methods, so any class can implement it. Its purpose is to inform any serializing process that you have taken the proper steps.

import java.io.Serializable;
public class Gorilla implements Serializable {
   private static final long serialVersionUID = 1L;
   private String name;
   private int age;
   private Boolean friendly;
   private transient String favoriteFood;
}

How to make a class serializable

  • The class must be marked Serializable.
  • Every instance member must be serializable, marked transient, or have a null value at the time of serialization.
  • Apply the second rule recursively — a serializable field whose own fields are not serializable breaks the chain.
public class Cat implements Serializable { private Tail tail = new Tail(); }
public class Tail implements Serializable { private Fur fur = new Fur(); }
public class Fur {}    // not Serializable → Cat is not serializable

Fix it by marking fur transient or by making Fur implement Serializable. Attempting to serialize an improperly built class throws NotSerializableException.

⚠ Exam Trap
  • A field declared as plain Object (e.g. private Object stripes = new Object();) makes the whole class not serializable — Object does not implement Serializable. The code compiles but throws at runtime.
  • Records are not automatically serializable. record R(String name) {} is not; record R(String name) implements Serializable {} is.
  • A serialVersionUID is recommended, not required.
  • Marking static fields transient has little effect — other than serialVersionUID, only instance members are serialized.

ObjectOutputStream and ObjectInputStream

// ObjectInputStream
public Object readObject() throws IOException, ClassNotFoundException
// ObjectOutputStream
public void writeObject(Object obj) throws IOException
void saveToFile(List<Gorilla> gorillas, File dataFile) throws IOException {
   try (var out = new ObjectOutputStream(
           new BufferedOutputStream(new FileOutputStream(dataFile)))) {
      for (Gorilla gorilla : gorillas)
         out.writeObject(gorilla);
   }
}

List<Gorilla> readFromFile(File dataFile) throws IOException, ClassNotFoundException {
   var gorillas = new ArrayList<Gorilla>();
   try (var in = new ObjectInputStream(
         new BufferedInputStream(new FileInputStream(dataFile)))) {
      while (true) {
         var object = in.readObject();
         if (object instanceof Gorilla g)
            gorillas.add(g);
      }
   } catch (EOFException e) {
      // File end reached
   }
   return gorillas;
}
  • When calling readObject(), null and -1 have no special meaning — someone may have serialized those values. So an infinite loop is used, terminated by EOFException.
  • readObject() declares a checked ClassNotFoundException since the class might not be available at deserialization.
  • available() cannot be used to detect the end — it only reports blocks readable without blocking, and can return 0 even when bytes remain.

The deserialization creation process

✓ Key Rule

On deserialization, the constructor and instance initializers of the serialized class are not called. Java calls the no-arg constructor of the first non-serializable parent class it finds in the hierarchy. Static and transient fields are ignored, and missing values take their Java defaults (null, 0).

// Mammal.java — NOT Serializable
public class Mammal {
   private int id;
   public Mammal() { this.id = 4; }
}

// Chimpanzee.java
public class Chimpanzee extends Mammal implements Serializable {
   private static final long serialVersionUID = 2L;
   private transient String name;
   private transient int age = 10;
   private static char type = 'C';
   { this.age = 14; }
   public Chimpanzee() { this("Unknown", 12, 'Q'); }
   public Chimpanzee(String name, int age, char type) {
      this.name = name; this.age = age; this.type = type; setId(9);
   }
}
Original:  [name=Ham,  age=2, type=B, id=9], [name=Enos, age=3, type=B, id=9]
From Disk: [name=null, age=0, type=B, id=4], [name=null, age=0, type=B, id=4]
  • name and age are transient → not written; they come back as null and 0.
  • type is static → not written; it shows whatever value was set last in the JVM.
  • Neither Chimpanzee constructor runs, and the instance initializer setting age = 14 does not run either.
  • Mammal is not Serializable, so its no-arg constructor runs and id becomes 4.
  • A subclass of a Serializable class is itself serializable, inheriting the interface.
★ Remember

You can customize serialization by declaring private readObject(ObjectInputStream) and writeObject(ObjectOutputStream) methods. These are not overrides — they are called automatically. Start readObject() with in.defaultReadObject() and end writeObject() with out.defaultWriteObject().

Section 06

Interacting with Users

The system streams

System.out and System.err are both PrintStream instances; System.in is an InputStream. System.err reports errors on a separate stream — an IDE might colour it differently, and a server might route it to a different log file.

var reader = new BufferedReader(new InputStreamReader(System.in));
String userInput = reader.readLine();
System.out.println("You entered: " + userInput);
⚠ Exam Trap

System streams are the only streams in this chapter not used in try-with-resources. They are static and shared by the whole application; closing them makes them permanently unavailable to all threads. Watch what happens:

try (var out = System.out) {}
System.out.println("Hello");      // prints NOTHING — fails silently

try (var err = System.err) {}
System.err.println("Hello");      // prints NOTHING — fails silently

var reader = new BufferedReader(new InputStreamReader(System.in));
try (reader) {}
String data = reader.readLine();     // IOException at runtime

The PrintStream cases fail silently because their methods throw no checked exceptions. Most InputStream implementations do throw if you operate on a closed stream.

The Console class

java.io.Console is a singleton, accessible only through a factory method:

Console c = new Console();          // DOES NOT COMPILE — constructors are private

Console console = System.console();
if (console != null) {
   String userInput = console.readLine();
   console.writer().println("You entered: " + userInput);
   console.flush();
} else {
   System.err.println("Console not available");
}
✓ Key Rule

System.console() returns null when a console is not available, depending on where the code runs. Always check for null before using it — code that calls c.readLine() straight after var c = System.console(); may throw a NullPointerException.

⚠ Exam Trap

Because not all classes support mark(), any question involving it usually has "may print" as the correct answer rather than "will always print." The readLimit passed to mark() says how many bytes you expect to read before reset(); exceeding it may throw. Calling mark()/reset() without checking markSupported() can throw at runtime.

// next values are TIGERS
System.out.print((char)is.read());   // T
is.skip(2);                          // skips I and G
is.read();                            // reads E but doesn't output it
System.out.print((char)is.read());   // R
System.out.print((char)is.read());   // S
// Prints TRS

skip() returns how many values were actually skipped — near the end of a stream, skip(1000) might return 20.

Discovering file attributes

Beyond isDirectory() and isRegularFile(), Files adds isSymbolicLink(), which File cannot do. Note that isDirectory() or isRegularFile() can return true for a symbolic link, as long as the link resolves to that type.

Files also exposes isHidden(), isReadable(), isWritable(), and isExecutable(). With the exception of isHidden(), these declare no checked exceptions and return false if the file does not exist.

// Read-only
var path = Path.of("/turtles/sea.txt");
BasicFileAttributes data = Files.readAttributes(path, BasicFileAttributes.class);
data.isDirectory();  data.isRegularFile();  data.isSymbolicLink();
data.size();         data.lastModifiedTime();

// Updatable view
BasicFileAttributeView view =
   Files.getFileAttributeView(path, BasicFileAttributeView.class);
BasicFileAttributes attributes = view.readAttributes();
FileTime lastModifiedTime = FileTime.fromMillis(
   attributes.lastModifiedTime().toMillis() + 10_000);
view.setTimes(lastModifiedTime, null, null);
⚠ Exam Trap

setTimes(lastModifiedTime, lastAccessTime, createTime) is available only on BasicFileAttributeView, never on the read-only BasicFileAttributes. Calling a.setTimes(...) on a BasicFileAttributes variable does not compile. Pass null for any value you don't want to modify.

Reading all attributes in one call means fewer round-trips to the file system, which is more performant than calling several individual methods — and views can expose file-system-specific attributes the Files methods cannot.

Traversing a directory tree

Depth-first search

  • Goes from root to an arbitrary leaf, then back up, filling in skipped paths
  • Uses a search depth limit to prevent endless searching
  • This is what the NIO.2 Stream API methods use

Breadth-first search

  • Processes all elements of each depth before the next
  • Balanced and predictable
  • Requires more memory — a list of visited nodes is maintained
public static Stream<Path> walk(Path start, FileVisitOption... options)
public static Stream<Path> walk(Path start, int maxDepth, FileVisitOption... options)
public long getPathSize(Path source) throws IOException {
   try (var s = Files.walk(source)) {
      return s.parallel()
            .filter(p -> !Files.isDirectory(p))
            .mapToLong(this::getSize)
            .sum();
   }
}
  • walk() uses lazy evaluation, so memory stays low even for huge trees.
  • The one-argument version uses a default max depth of Integer.MAX_VALUE. A depth of 0 means the current path itself.
  • The helper getSize() wraps Files.size()'s IOException in an UncheckedIOException so it can be used inside a lambda.
✓ Key Rule

walk() is the odd one out: most NIO.2 methods follow symbolic links by default and are disabled with NOFOLLOW_LINKS, but walk() does not follow them unless you pass FileVisitOption.FOLLOW_LINKS. When that option is used, walk() tracks visited paths and throws FileSystemLoopException if a path is visited twice (a cycle).

Searching a directory with find()

public static Stream<Path> find(Path start,
   int maxDepth,
   BiPredicate<Path, BasicFileAttributes> matcher,
   FileVisitOption... options) throws IOException
var path = Path.of("/bigcats");
long minSize = 1_000;
try (var s = Files.find(path, 10,
      (p, a) -> a.isRegularFile()
         && p.toString().endsWith(".java")
         && a.size() > minSize)) {
   s.forEach(System.out::println);
}
  • find() behaves like walk() but takes a BiPredicate and requires a depth limit.
  • The two BiPredicate parameters are a Path and a BasicFileAttributes — Java retrieves the attributes for you.
  • A maxDepth of 0 searches only the starting path itself, so a search for symbolic links under a directory would print nothing.
⚠ Exam Trap

Files.walk() returns a Stream<Path>, so filter() on it takes a one-parameter Predicate. A lambda like .filter((p, a) -> ...) after walk() does not compile — the two-parameter BiPredicate form belongs to find().

★ Remember

An older way to list a directory is Files.newDirectoryStream(path, "*.{txt,java}"), returning a DirectoryStream<Path> you iterate with a for-each loop. Prefer Files.find() in new code, but recognise either on the exam.

Short Recap

Files and paths

  • Absolute paths start with / or a drive letter; everything else is relative. Path symbols: . = current, .. = parent.
  • File uses constructors; Path is an interface created via Path.of(), Paths.get(), FileSystems, or a URI. Convert with toPath() / toFile().

Operating on paths

  • Path is immutable — unassigned method calls do nothing. toString() is the only method returning a String.
  • getNameCount(), getName(), and subpath() exclude the root and throw IllegalArgumentException on bad indexes.
  • resolve() = concatenation (an absolute argument wins). relativize() needs both paths the same kind. normalize() is textual; toRealPath() hits the file system and throws if missing.
  • createDirectory() vs createDirectories(); delete() vs deleteIfExists(); copy()/move() need REPLACE_EXISTING and never place a file "into" a directory.

I/O streams

  • Byte (InputStream/OutputStream) vs character (Reader/Writer); input vs output; low-level (file classes only) vs high-level (everything else).
  • Never mix families when wrapping. InputStream/Reader/etc. are abstract. No PrintReader exists.
  • read() returns int, with -1 for end of stream; always honour the return value of the buffered overload.

Files convenience methods

  • readString(), readAllBytes(), readAllLines() load everything into memory; lines() is lazy and returns a Stream.
  • NIO.2 stream methods must be closed with try-with-resources.

Serialization

  • Serializable is a marker interface; every instance member must be serializable, transient, or null. Records must implement it explicitly.
  • On deserialization no constructor or instance initializer of the serialized class runs — only the no-arg constructor of the first non-serializable parent.
  • readObject() is looped until EOFException; it declares ClassNotFoundException.

Users and advanced APIs

  • System.out/System.err are PrintStream (silent failures); System.in is an InputStream. Don't close them.
  • Console is a singleton from System.console() that may be null; readPassword() returns char[].
  • mark()/reset()/skip(); check markSupported() first.
  • readAttributes() is read-only, getFileAttributeView() is updatable (setTimes()). walk() doesn't follow links by default; find() takes a BiPredicate and requires a depth.

SECTION 01

Exception বোঝা

Exception হলো Java-র বলার ভাষা — "আমি আর পারছি না, এবার তুমি সামলাও।" কোনো method হয় exception-টা নিজে handle করবে, নয়তো declare করে caller-এর ঘাড়ে দায়িত্ব দেবে। সব exception event-ই Throwable class hierarchy-র object — মনে রাখবেন, সবার নামে "Exception" শব্দটা থাকে না।

Throwable hierarchy

                java.lang.Throwable
                /                 \
      java.lang.Exception     java.lang.Error   // Error = unchecked, ধরবেন না
             |
   java.lang.RuntimeException                   // RuntimeException = unchecked

// Exception (কিন্তু RuntimeException নয়) = CHECKED

Unchecked exceptionRuntimeException-এর subclassহ্যাঁনা

✓ KEY RULE — Handle or Declare

Method-এর ভিতরে যত checked exception throw হতে পারে, প্রতিটিকে হয় compatible try/catch দিয়ে handle করতে হবে, নয়তো method signature-এ throws দিয়ে declare করতে হবে। Unchecked exception (RuntimeException, Error)-এর জন্য এটা লাগে না — তবে redundant declare করলেও code compile হয়।

void fall(int distance) throws IOException {   // declare…
   if(distance > 10) { throw new IOException(); }
}

void fall(int distance) {                       // …অথবা handle
   try {
      if(distance > 10) { throw new IOException(); }
   } catch (Exception e) {          // superclass দিয়ে catch করা বৈধ
      e.printStackTrace();
   }
}
★ REMEMBER

Throwable হলো সবার parent — Error-ও এর অন্তর্ভুক্ত। Throwable/Error catch করা সম্ভব, কিন্তু করা উচিত নয়। Error মানে এত বড় সমস্যা (memory শেষ, disk উধাও) যে recover করার চেষ্টা করাই অর্থহীন।

SECTION 02

Exception Throw করা

throw

  • Code block-এর ভিতরের একটা statement।
  • আসলেই একটা exception object throw (বা rethrow) করে।
  • throw new RuntimeException();

throws

  • শুধু method declaration-এর শেষে বসে।
  • বলে যে method-টা exception throw করতে পারে — নাও করতে পারে।
  • void fall() throws IOException {}

Exception একটা object — reference-এ রেখে পরে throw করা যায়:

var e = new RuntimeException();
throw e;                          // বৈধ

throw RuntimeException();         // DOES NOT COMPILE — new keyword নেই!
⚠ EXAM TRAP — throw-এর পরে unreachable code 
try {
   throw new RuntimeException();
   throw new ArrayIndexOutOfBoundsException();  // DOES NOT COMPILE
} catch (Exception e) {}

প্রথম throw-এর কারণে দ্বিতীয় statement কখনো execute হবে না → compiler unreachable code error দেয়।

Checked exception declare করা method call করলে

class NoMoreCarrotsException extends Exception {}

public class Bunny {
   private void eatCarrot() throws NoMoreCarrotsException {}
   public void hopAround() {
      eatCarrot();                // DOES NOT COMPILE
   }
}

Caller-কেও handle অথবা declare করতে হবে — এমনকি eatCarrot() বাস্তবে কিছু throw না করলেও। শুধু declare করাই caller-কে বাধ্য করার জন্য যথেষ্ট।

⚠ EXAM TRAP — যে checked exception throw হতেই পারে না, সেটা catch করা 
private void eatCarrot() {}          // কিছুই declare করে না
public void bad() {
   try { eatCarrot(); }
   catch (NoMoreCarrotsException e) { // DOES NOT COMPILE
      System.out.print("sad rabbit");
   }
}

try block-এর ভিতরে ওই checked exception (বা তার subclass) throw হওয়ার কোনো সম্ভাবনাই না থাকলে catch block-টি unreachable → compiler error। এই rule unchecked exception-এর জন্য প্রযোজ্য নয় — catch (RuntimeException e) সবসময়ই বৈধ।

Overriding ও exception

OVERRIDING + CHECKED EXCEPTION

  1. Overridden method inherited method-এর চেয়ে নতুন বা broader checked exception declare করতে পারবে না।
  2. কম exception, একটাও না, বা declared exception-এর subclass declare করা সম্পূর্ণ বৈধ।
  3. Unchecked exception ইচ্ছেমতো declare করা যায় — এগুলো contract-এর অংশ নয়।
class Hopper { public void hop() {} }
public class Bunny extends Hopper {
   public void hop() throws CanNotHopException {}  // DOES NOT COMPILE
}
// উল্টোটা ঠিক আছে: parent throws করে, child কিছুই declare করে না।

Exception print করার তিন উপায়

} catch (Exception e) {
   System.out.println(e);              // java.lang.RuntimeException: cannot hop
   System.out.println(e.getMessage()); // cannot hop
   e.printStackTrace();                // পুরো stack trace, method call hierarchy সহ
}

পরীক্ষার জন্য তিনটি group চিনতে হবে — unchecked (RuntimeException), checked, ও Error — সাথে কে throw করে (JVM নাকি programmer) এবং দুটি inheritance pair।

Unchecked (RuntimeException) class

  • NumberFormatException extends IllegalArgumentException
  • FileNotFoundException ও NotSerializableException extends IOException

এই দুটি pair-ই catch block-এর order আর multi-catch-এর বৈধতা নির্ধারণ করে (Section 04–05)।

ClassCastException — compile time বনাম runtime

String type = "moose";
Integer number = (Integer) type;   // DOES NOT COMPILE (unrelated type)

String type = "moose";
Object obj = type;
Integer number = (Integer) obj;    // compile হয়, কিন্তু runtime-এ ClassCastException

Helpful NullPointerException

public class Frog {
   static String name;
   public void hop() {
      System.out.print(name.toLowerCase() + " is hopping");
   }
   public static void main(String[] args) { new Frog().hop(); }
}
// Cannot invoke "String.toLowerCase()" because "Frog.name" is null
  • Instance/static variable-এর ক্ষেত্রে JVM variable-এর নাম দেখায় (Frog.name)।
  • Local variable ও parameter-এর ক্ষেত্রে <parameterX> / <localX> দেখায় — compile করলে নাম হারিয়ে যায়। তবে javac -g:vars দিয়ে compile করলে আসল নাম ফিরে আসে।

Checked exception ও Error

Checked (handle/declare করতেই হবে)

  • IOException — file read/write সমস্যা
  • FileNotFoundException — file নেই (IOException-এর subclass)
  • NotSerializableException — non-serializable class (de)serialize করা (IOException-এর subclass)
  • ParseException — input parse-এ সমস্যা (যেমন NumberFormat.parse())

Error (unchecked, catch করবেন না)

  • ExceptionInInitializerError — static initializer exception throw করে handle করেনি
  • StackOverflowError — infinite recursion
  • NoClassDefFoundError — compile time-এ class ছিল, runtime-এ নেই
⚠ EXAM TRAP

Answer option-এ "does not compile" আর "throws an exception" দুটোই থাকলে সাবধান: null reference-এ method call বা invalid array/List index — এই code দিব্যি compile হয়; সঠিক উত্তর runtime exception, compiler error নয়।

SECTION 04

try / catch ও Catch Block Chaining

TRY STATEMENT-এর SYNTAX RULE

  1. try ও catch block-এ braces {} বাধ্যতামূলক (if/loop-এর মতো বাদ দেওয়া যায় না)।
  2. Traditional try-এর পরে catch অথবা finally থাকতেই হবে — "lonely try" compile হয় না।
  3. পরীক্ষায় block আর clause শব্দ দুটো একই অর্থে ব্যবহৃত হয়।
try                     // DOES NOT COMPILE — braces নেই
   fall();
catch (Exception e)
   System.out.println("get up");

try {                   // DOES NOT COMPILE — lonely try, catch/finally নেই
   fall();
}

Catch block chaining — order গুরুত্বপূর্ণ

সর্বোচ্চ একটি catch block চলে: যেটি প্রথম exception-টি handle করতে পারে। Superclass catch যদি subclass catch-এর আগে থাকে, subclass catch-টি unreachable → compiler error।

try {
   seeAnimal();
} catch (ExhibitClosed e) {              // superclass আগে…
   System.out.print("not today");
} catch (ExhibitClosedForLunch e) {      // DOES NOT COMPILE — unreachable
   System.out.print("try back later");
}
⚠ EXAM TRAP — লুকানো subclass ordering 
try {
} catch (IllegalArgumentException e) {
} catch (NumberFormatException e) {   // DOES NOT COMPILE
}

NumberFormatException IS-A IllegalArgumentException, তাই দ্বিতীয় block unreachable। একই trick IOException-এর পরে FileNotFoundException দিয়েও আসে।

⚠ EXAM TRAP — catch variable-এর scope 
} catch (NumberFormatException e1) {
   System.out.println(e1);
} catch (IllegalArgumentException e2) {
   System.out.println(e1);            // DOES NOT COMPILE — e1 scope-এর বাইরে
}

Exception variable শুধু নিজের catch block-এর ভিতরেই scope-এ থাকে।

SECTION 05

Multi-catch Block

Multi-catch block একটি handler দিয়ে একাধিক exception type ধরে, pipe (|) দিয়ে আলাদা করা হয় — variable-এর নাম একটাই, একবারই, শেষে।

try {
   System.out.println(Integer.parseInt(args[1]));
} catch (ArrayIndexOutOfBoundsException | NumberFormatException e) {
   System.out.println("Missing or invalid input");
}
catch(Exception1 e | Exception2 e | Exception3 e)    // DOES NOT COMPILE
catch(Exception1 e1 | Exception2 e2 | Exception3 e3) // DOES NOT COMPILE
catch(Exception1 | Exception2 | Exception3 e)        // compile হয় ✓
⚠ EXAM TRAP — related type redundant 
try {
   throw new IOException();
} catch (FileNotFoundException | IOException p) {}  // DOES NOT COMPILE

Subclass আর তার superclass এক multi-catch-এ থাকতে পারে না — subclass-টি redundant ("already caught by the alternative IOException")। সমাধান: শুধু IOException catch করুন।

Chained catch block

  • Order গুরুত্বপূর্ণ: subclass আগে, superclass পরে।
  • প্রতিটি block-এর নিজস্ব variable।

Multi-catch (এক block)

  • Type-এর order গুরুত্বহীন।
  • শেষে একটাই shared variable; subclass–superclass pair নিষিদ্ধ।
SECTION 06

finally Block

FINALLY-র RULE

  1. Order নির্দিষ্ট: try → catch → finally। ভুল order-এ compile হয় না।
  2. finally থাকলে catch optional (try+finally বৈধ)।
  3. try-with-finally-তে একবার ঢুকলে finally সবসময় execute হয় — exception হোক বা না হোক।
  4. ব্যতিক্রম #১: try/catch-এ System.exit() — finally চলে না।
  5. finally সবসময় শুরু হয়, কিন্তু শেষ নাও হতে পারে (নিজেই exception throw করতে পারে, যেমন NPE)।
try {                // DOES NOT COMPILE — finally-র পরে catch
   fall();
} finally {
   System.out.println("all better");
} catch (Exception e) {
   System.out.println("get up");
}

Classic output-tracing প্রশ্ন

StringBuilder sb = new StringBuilder();
try {                 sb.append("t");
} catch (Exception e) { sb.append("c");
} finally {           sb.append("f");
}
sb.append("a");
System.out.print(sb.toString());   // tfa
  • Exception নেই → try t append করে, catch skip হয়।
  • finally সবসময় চলে → f।
  • try statement শেষে execution চলতে থাকে → a। Output: tfa।
⚠ EXAM TRAP — finally-র ভিতরের return জেতে 
int goHome() {
   try {
      // এখানে exception হতেও পারে, নাও পারে
      System.out.print("1");  return -1;
   } catch (Exception e) {
      System.out.print("2");  return -2;
   } finally {
      System.out.print("3");  return -3;
   } }

Print হয় 13 (exception না হলে) বা 23 (exception হলে) — কিন্তু return value সবসময় -3। Method complete হওয়ার ঠিক আগে finally চলে এবং আগের সব return-কে override করে।

SECTION 07

Try-with-Resources

Try-with-resources (অর্থাৎ automatic resource management) try clause-এ খোলা সব resource স্বয়ংক্রিয়ভাবে close করে দেয়। Compiler ভিতরে ভিতরে এটাকে try + implicit finally-তে রূপান্তর করে, যেখানে close() call হয়।

TRY-WITH-RESOURCES-এর RULE

  1. শুধু AutoCloseable implement করা type ব্যবহার করা যায় (Closeable extends AutoCloseable, দুটোই চলে)।
  2. Resource-গুলো semicolon (;) দিয়ে আলাদা হয়; প্রতিটি declaration-এ নিজস্ব data type লাগে (var চলবে)।
  3. catch ও finally দুটোই optional (traditional try-এর মতো নয়)।
  4. try block শেষে resource close হয়, declaration-এর উল্টো (REVERSE) order-এ।
  5. Implicit finally (close call) programmer-এর লেখা catch/finally-র আগে চলে।
  6. Resource variable-এর scope শুধু try block-এর ভিতরে।
interface AutoCloseable {
   public void close() throws Exception;   // impl subclass throw করতে পারে, বা কিছুই না
}

try (String reptile = "lizard") {}          // DOES NOT COMPILE — String AutoCloseable নয়

try (MyFileClass is = new MyFileClass(1),   // DOES NOT COMPILE — comma + type নেই
   os = new MyFileClass(2)) {}
try (MyFileClass ab = new MyFileClass(1),   // DOES NOT COMPILE — ; এর বদলে comma
   MyFileClass cd = new MyFileClass(2)) {}

Order of operations — এই output মুখস্থ করুন

public class MyFileClass implements AutoCloseable {
   private final int num;
   public MyFileClass(int num) { this.num = num; }
   @Override public void close() { System.out.println("Closing: " + num); }
}

try (MyFileClass bookReader = new MyFileClass(1);
      MyFileClass movieReader = new MyFileClass(2)) {
   System.out.println("Try Block");
   throw new RuntimeException();
} catch (Exception e) {
   System.out.println("Catch Block");
} finally {
   System.out.println("Finally Block");
}
  • Try Block — try body চলে, তারপর throw।
  • Closing: 2 তারপর Closing: 1 — implicit finally উল্টো order-এ close করে, catch-এর আগেই।
  • Catch Block — তারপর Finally Block।

Effectively final resource

আগে declare করা variable-ও resource হিসেবে ব্যবহার করা যায় (শুধু নাম লিখে, ; দিয়ে আলাদা করে) — যদি সেটা final বা effectively final হয়:

final var bookReader = new MyFileClass(4);
MyFileClass movieReader = new MyFileClass(5);       // effectively final
try (bookReader; var tvReader = new MyFileClass(6); movieReader) {
   System.out.println("Try Block");
} finally { System.out.println("Finally Block"); }
// Try Block → Closing: 5 → Closing: 6 → Closing: 4 → Finally Block
⚠ EXAM TRAP — effectively final নয় / close-এর পরে ব্যবহার 
var writer = Files.newBufferedWriter(path);
try (writer) {          // DOES NOT COMPILE — নিচে writer reassign হয়েছে
   writer.append("Welcome to the zoo!");
}
writer = null;

// আলাদা কথা: try block-এর পরে resource-এ write করা compile হয়,
// কিন্তু runtime-এ IOException ("Stream closed") দেয়।
⚠ EXAM TRAP — scope শেষ হয় try block-এই 
try (Scanner s = new Scanner(System.in)) {
   s.nextLine();
} catch(Exception e) {
   s.nextInt();          // DOES NOT COMPILE
} finally {
   s.nextInt();          // DOES NOT COMPILE
}

catch/finally চলার সময় resource ইতিমধ্যে closed এবং scope-এর বাইরে।

SECTION 08

Suppressed Exceptions

একাধিক exception throw হলে প্রথমটি হয় primary exception; বাকিগুলো তার সাথে suppressed হিসেবে যুক্ত হয় (getSuppressed() দিয়ে পাওয়া যায়)। Typical case: try block throw করল, তারপর close()-ও throw করল।

1: public class JammedTurkeyCage implements AutoCloseable {
2:    public void close() throws IllegalStateException {
3:       throw new IllegalStateException("Cage door does not close");
4:    }
5:    public static void main(String[] args) {
6:       try (JammedTurkeyCage t = new JammedTurkeyCage()) {
7:          throw new IllegalStateException("Turkeys ran off");
8:       } catch (IllegalStateException e) {
9:          System.out.println("Caught: " + e.getMessage());
10:         for (Throwable t: e.getSuppressed())
11:            System.out.println("Suppressed: " + t.getMessage());
12:      } }
  • Line 7 primary exception throw করে ("Turkeys ran off")।
  • Java automatic ভাবে close() call করে → সেটার exception হয় suppressed।
  • Output: Caught: Turkeys ran off তারপর Suppressed: Cage door does not close।
✓ KEY RULE — catch মেলে PRIMARY exception-এর সাথে

try block যদি RuntimeException throw করে আর close() যদি IllegalStateException throw করে, তাহলে catch (IllegalStateException e) match করে না — primary RuntimeException-টি caller-এর কাছে চলে যায় (suppressed-টি সাথে নিয়ে)।

✓ KEY RULE — একাধিক resource fail করলে

Resource উল্টো order-এ close হয়, তাই একাধিক close() throw করলে সবার শেষে declare করা resource-এর exception প্রথমে throw হয় → সেটাই primary, বাকিগুলো suppressed।

⚠ EXAM TRAP — finally exception হারিয়ে ফেলে (suppress নয়) 
try (JammedTurkeyCage t = new JammedTurkeyCage()) {
   throw new IllegalStateException("Turkeys ran off");
} finally {
   throw new RuntimeException("and we couldn't find them");
}
// শুধু "and we couldn't find them" propagate হয় — try block-এর
// exception (এবং তার suppressed exception) সম্পূর্ণ হারিয়ে যায়।

Suppression শুধু try clause-এ throw হওয়া exception-এর জন্য (close সহ)। Programmer-এর লেখা finally-তে throw হওয়া exception আগের সবকিছু replace করে দেয় — bad practice, কিন্তু বৈধ।

Number Format করা — DecimalFormat

NumberFormat একটি abstract class, যার format(double) / format(long) আছে। Concrete DecimalFormat class একটি pattern String নেয়। পরীক্ষায় মাত্র দুটি symbol জানলেই চলে:

Symbolঅর্থExample

Internationalization ও Locale

Internationalization (i18n)

  • Program-কে এমনভাবে design করা যেন পরে adapt করা যায়: string-গুলো properties file-এ externalize করা, সঠিক formatter ব্যবহার করা।

Localization (l10n)

  • আসলেই একাধিক locale support করা: string translate করা, locale অনুযায়ী সঠিক date ও number format দেখানো।

LOCALE FORMAT-এর RULE

  1. Language code: lowercase, সবসময় বাধ্যতামূলক — যেমন en।
  2. Country code: UPPERCASE, optional, underscore দিয়ে যুক্ত — যেমন en_US।
  3. বৈধ form মাত্র দুটি: en এবং en_US। আর কিছু না।
US      // invalid — language ছাড়া country হয় না
enUS    // invalid — underscore নেই
US_en   // invalid — country আর language উল্টো
EN      // invalid — language lowercase হতে হবে

Locale পাওয়ার তিনটি (non-deprecated) উপায়

// ১. Built-in constant
System.out.println(Locale.GERMAN);   // de       (শুধু language)
System.out.println(Locale.GERMANY);  // de_DE    (language + country)

// ২. Factory method
Locale.of("fr");           // fr
Locale.of("hi", "IN");     // hi_IN

// ৩. Builder — property যেকোনো order-এ
Locale l1 = new Locale.Builder().setLanguage("en").setRegion("US").build();
Locale l2 = new Locale.Builder().setRegion("US").setLanguage("en").build();
★ REMEMBER
  • new Locale("en","US") — এই constructor-গুলো deprecated; constant / Locale.of() / Builder ব্যবহার করুন।
  • xx_XX-এর মতো invalid locale Java দিব্যি তৈরি করে দেয় — কোনো exception হয় না, শুধু কোনো কিছুর সাথে match করবে না।
  • Locale.setDefault(locale) শুধু সেই একবারের program run-এ প্রভাব ফেলে।

  1. প্রথমে সবচেয়ে বড় range নির্ধারণ করে: thousand (K), million (M), billion (B), trillion (T)।

✓ KEY RULE

সংক্ষিপ্ত রিভিউ

Exception type

  • Checked = Exception বাদে RuntimeException → handle অথবা declare। Unchecked = RuntimeException + Error। Error/Throwable কখনো catch করবেন না।

throw / throws ও overriding

  • throw = statement, throws = declaration; new ছাড়া throw RuntimeException() compile হয় না। Override-এ কম/narrower checked exception চলবে, নতুন/broader নয়।

Exception class

  • NFE extends IAE; FNFE ও NotSerializableException extends IOException। JVM throw করে ArithmeticException/AIOOBE/CCE/NPE; programmer throw করে IAE/NFE।

try/catch/finally

  • Subclass catch superclass-এর আগে; catch variable নিজের block-এ scoped; finally সবসময় চলে (System.exit() ছাড়া) এবং সেখানকার return আগের return-দের override করে।

Multi-catch

  • শেষে একটাই variable; subclass–superclass pair নিষিদ্ধ; type-এর order গুরুত্বহীন।

Try-with-resources

  • শুধু AutoCloseable; semicolon দিয়ে আলাদা; implicit finally উল্টো order-এ close করে এবং catch/finally-র আগে চলে; resource-এর scope শুধু try-তে; আগে-declare করা resource (effectively) final হতে হবে।

Suppressed exception

  • প্রথম throw = primary, close()-এর failure-গুলো তাতে suppressed হয়; programmer-এর finally-তে throw হওয়া exception সবকিছু replace করে (হারিয়ে যায়)।

Formatting

  • DecimalFormat: # বাদ দেয়, 0 pad করে, fraction round হয়। Date symbol: M/m, H/h case-sensitive; type-এর সাথে বেমানান symbol → runtime exception; literal text '…' দিয়ে escape, '' = literal quote।

Locale ও localization

  • Format: en বা en_US (lowercase language বাধ্যতামূলক, UPPERCASE country optional)। Constructor deprecated → constant / Locale.of() / Builder। parse() checked ParseException throw করে এবং locale-sensitive। Compact: ৩ digit + K/M/B/T, default SHORT।

Resource bundle

  • Bundle বাছাই: requested (full→lang) → default (full→lang) → base bundle → MissingResourceException। Value আসে শুধু matched hierarchy + parent থেকে।

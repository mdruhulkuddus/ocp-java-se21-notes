Q1Exception Types

Which of the following exceptions must be handled or declared in the method where they are thrown? (Choose all that apply.)

class Apple  extends RuntimeException {}
class Orange extends Exception {}
class Banana extends Error {}
class Pear   extends Apple {}
class Tomato extends Orange {}
  • A. Apple
  • B. Orange
  • C. Banana
  • D. Pear
  • E. Tomato
Show Answer B, E

Checked exceptions inherit Exception but not RuntimeException — that's Orange and Tomato (Tomato extends Orange). Apple and Pear are unchecked (RuntimeException subclasses), and Banana is an Error, which is unchecked and should not be handled or declared.

Q2throw / throws

What is the result of the following statement inside a method body?

throw RuntimeException();
  • A. A RuntimeException is thrown at runtime.
  • B. The code compiles but nothing is thrown.
  • C. The code does not compile.
  • D. An Error is thrown at runtime.
Show Answer C · Does not compile

The new keyword is missing — exceptions must be instantiated (throw new RuntimeException();). Without new, Java treats this as a call to a method named RuntimeException(), which doesn't exist.

Q3try / catch

Which statements about this snippet are true? (Choose all that apply.)

3: try {
4:    throw new RuntimeException();
5:    throw new ArrayIndexOutOfBoundsException();
6: } catch (Exception e) {}
  • A. The code compiles and line 4's exception is caught.
  • B. Line 5 does not compile because it is unreachable code.
  • C. Line 6 does not compile because Exception is too broad.
  • D. Removing line 5 makes the code compile.
Show Answer B, D

Line 4 always throws, so line 5 can never execute — the compiler reports unreachable code (B). Removing line 5 leaves a legal try/catch (D). A is wrong because the code doesn't compile at all; C is wrong — catching a superclass like Exception is always allowed.

Q4Checked Exceptions

Why does the following code not compile?

class NoMoreCarrotsException extends Exception {}

public class Bunny {
   private void eatCarrot() throws NoMoreCarrotsException {}
   public void hopAround() {
      eatCarrot();
   }
}
  • A. eatCarrot() never actually throws the exception, so declaring it is an error.
  • B. hopAround() must handle or declare the checked exception.
  • C. A private method cannot declare a checked exception.
  • D. The code compiles as written.
Show Answer B

NoMoreCarrotsException is checked, and merely declaring it on eatCarrot() forces every caller to handle or declare it. A is false — declaring an unused checked exception is legal; C is false — visibility is irrelevant.

Q5Unreachable Catch

What is the result of compiling this method?

private void eatCarrot() {}   // declares no exceptions
public void bad() {
   try {
      eatCarrot();
   } catch (NoMoreCarrotsException e) {   // checked exception
      System.out.print("sad rabbit");
   }
}
  • A. Compiles; catch block simply never runs.
  • B. Does not compile — the catch block is unreachable.
  • C. Compiles; throws an exception at runtime.
  • D. Does not compile — eatCarrot() must declare the exception.
Show Answer B

Nothing in the try block can throw the checked NoMoreCarrotsException, so the catch is unreachable → compiler error. Note the rule applies only to checked exceptions — catching RuntimeException here would compile fine.

Q6Overriding

Given class Hopper { public void hop() {} }, which overrides of hop() in a subclass compile? (Choose all that apply.)

  • A. public void hop() throws CanNotHopException {} (checked)
  • B. public void hop() {}
  • C. public void hop() throws RuntimeException {}
  • D. public void hop() throws Exception {}
Show Answer B, C

An override may not add new or broader checked exceptions than the parent (which declares none) — so A and D fail. Declaring an unchecked exception (C) is always allowed, and declaring nothing (B) is trivially fine.

Q7NPE Output

What is the output of this program?

public class Frog {
   static String name;
   public void hop() {
      System.out.print(name.toLowerCase() + " is hopping");
   }
   public static void main(String[] args) {
      new Frog().hop();
   }
}
  • A. null is hopping
  • B. The code does not compile.
  • C. A NullPointerException naming Frog.name is thrown.
  • D. A NullPointerException naming <local1> is thrown.
Show Answer C

Static variables default to null, so name.toLowerCase() throws an NPE. Helpful NullPointerExceptions print the variable name for instance/static variables ("Frog.name" is null); the <localX>/<parameterX> form appears only for local variables and parameters compiled without -g:vars.

Q8Exception Classes

Which statements are true? (Choose all that apply.)

  • A. NumberFormatException is a subclass of IllegalArgumentException.
  • B. FileNotFoundException is a subclass of IOException.
  • C. ParseException is an unchecked exception.
  • D. StackOverflowError must be handled or declared.
  • E. ClassCastException is thrown by the JVM.
Show Answer A, B, E

A and B are the two inheritance pairs to memorize; E is a JVM-thrown runtime exception. C is false — ParseException is checked. D is false — errors are unchecked and should not be handled or declared.

Q9Catch Order

What is the result of the following?

public void visitSnakes() {
   try {
   } catch (IllegalArgumentException e) {
   } catch (NumberFormatException e) {
   }
}
  • A. Compiles; neither catch block ever runs.
  • B. Does not compile — the second catch block is unreachable.
  • C. Does not compile — an empty try block is illegal.
  • D. Does not compile — unchecked exceptions cannot be caught.
Show Answer B

NumberFormatException is a subclass of IllegalArgumentException, so anything it would catch is already caught by the first block → unreachable code. An empty try block (C) is legal, and unchecked exceptions can always be caught (D).

Q10Catch Scope

Why does this code not compile?

} catch (NumberFormatException e1) {
   System.out.println(e1);
} catch (IllegalArgumentException e2) {
   System.out.println(e1);
}
  • A. Two catch blocks cannot both print.
  • B. e1 is out of scope in the second catch block.
  • C. The catch order is wrong.
  • D. It compiles as written.
Show Answer B

A catch variable is in scope only within its own catch block, so e1 cannot be referenced from the second block. The order (subclass NumberFormatException first) is actually correct, so C is wrong.

Q11Multi-catch

Which of the following catch clauses compile? (Choose all that apply.)

  • A. catch(Exception1 e | Exception2 e | Exception3 e)
  • B. catch(Exception1 e1 | Exception2 e2 | Exception3 e3)
  • C. catch(Exception1 | Exception2 | Exception3 e)
  • D. catch(FileNotFoundException | IOException e)
  • E. catch(ArrayIndexOutOfBoundsException | NumberFormatException e)
Show Answer C, E

Multi-catch takes exactly one variable name, written once at the end (kills A and B). Related types are forbidden — FileNotFoundException is a subclass of IOException, making D redundant and a compiler error. E's two types are unrelated, so it's fine.

Q12finally

What does this print, assuming a and b are both 0?

try {
   System.out.print(a / b);
} catch (ArithmeticException e) {
   System.out.print("0");
} finally {
   System.out.print("done");
}
  • A. 0
  • B. 0done
  • C. done0
  • D. An uncaught exception is thrown.
Show Answer B · 0done

0 / 0 throws ArithmeticException, the catch block prints 0, then finally always runs and prints done. finally executes after the catch block, so C is reversed.

Q13finally

What does main print, and what does goHome() return, if no exception is thrown on the marked line?

int goHome() {
   try {
      // Optionally throw an exception here
      System.out.print("1");
      return -1;
   } catch (Exception e) {
      System.out.print("2");
      return -2;
   } finally {
      System.out.print("3");
      return -3;
   } }
  • A. Prints 1, returns -1
  • B. Prints 13, returns -1
  • C. Prints 13, returns -3
  • D. Prints 123, returns -3
Show Answer C · "13", returns -3

The try prints 1 and reaches return -1, but the finally block runs before the method completes: it prints 3 and its own return -3 interrupts and replaces the earlier return. The catch never runs, so 2 is never printed.

Q14finally

Which statements about finally are true? (Choose all that apply.)

  • A. A traditional try statement without a catch block requires a finally block.
  • B. A try-with-resources statement without a catch block requires a finally block.
  • C. If System.exit() is called in the try block, the finally block does not run.
  • D. A finally block that starts executing is guaranteed to finish executing.
Show Answer A, C

A traditional try needs catch and/or finally (A). Try-with-resources has an implicit finally, so both are optional (B is false). System.exit() is the one exception to "finally always runs" (C). A finally block always starts but may not finish — it can itself throw, e.g. an NPE (D is false).

Q15Try-with-Resources

Which of the following try-with-resources headers compile, given MyFileClass implements AutoCloseable? (Choose all that apply.)

  • A. try (MyFileClass a = new MyFileClass(1), MyFileClass b = new MyFileClass(2))
  • B. try (MyFileClass a = new MyFileClass(1); MyFileClass b = new MyFileClass(2))
  • C. try (var a = new MyFileClass(1))
  • D. try (String reptile = "lizard")
Show Answer B, C

Resources are separated by semicolons, not commas (A fails). var is allowed since resources are local variables (C). String does not implement AutoCloseable, so D fails.

Q16Try-with-Resources

What does this program print?

public class MyFileClass implements AutoCloseable {
   private final int num;
   public MyFileClass(int num) { this.num = num; }
   @Override public void close() { System.out.println("Closing: " + num); }

   public static void main(String... xyz) {
      try (MyFileClass bookReader = new MyFileClass(1);
            MyFileClass movieReader = new MyFileClass(2)) {
         System.out.println("Try Block");
         throw new RuntimeException();
      } catch (Exception e) {
         System.out.println("Catch Block");
      } finally {
         System.out.println("Finally Block");
      } } }
  • A. Try Block → Catch Block → Closing: 2 → Closing: 1 → Finally Block
  • B. Try Block → Closing: 1 → Closing: 2 → Catch Block → Finally Block
  • C. Try Block → Closing: 2 → Closing: 1 → Catch Block → Finally Block
  • D. Try Block → Catch Block → Finally Block → Closing: 2 → Closing: 1
Show Answer C

Resources close at the end of the try block, in reverse declaration order (2 then 1), via the implicit finally — which runs before the programmer's catch and finally blocks.

Q17Effectively Final

Why does line 32 not compile?

31: var writer = Files.newBufferedWriter(path);
32: try (writer) {
33:    writer.append("Welcome to the zoo!");
34: }
35: writer = null;
  • A. A resource must always be declared inside the try clause.
  • B. writer is not effectively final because it is reassigned on line 35.
  • C. var cannot be used with resources.
  • D. It compiles; line 33 throws an exception instead.
Show Answer B

A pre-declared variable may be used as a resource only if it is final or effectively final. The assignment on line 35 disqualifies writer, so line 32 is a compiler error. A and C are both false statements about try-with-resources.

Q18Resource Scope

How many lines of this snippet do not compile?

3: try (Scanner s = new Scanner(System.in)) {
4:    s.nextLine();
5: } catch(Exception e) {
6:    s.nextInt();
7: } finally {
8:    s.nextInt();
9: }
  • A. Zero — it compiles.
  • B. One (line 6 only).
  • C. Two (lines 6 and 8).
  • D. Three (lines 4, 6, and 8).
Show Answer C · Lines 6 and 8

The resource s is in scope only inside the try block. By the time catch/finally run, the implicit finally has already closed it and it is out of scope — so both references fail to compile. Line 4 is inside the try block and is fine.

Q19Suppressed

What does this program print?

1: public class JammedTurkeyCage implements AutoCloseable {
2:    public void close() {
3:       throw new IllegalStateException("Cage door does not close");
4:    }
5:    public static void main(String[] args) {
6:       try (JammedTurkeyCage t = new JammedTurkeyCage()) {
7:          throw new IllegalStateException("Turkeys ran off");
8:       } catch (IllegalStateException e) {
9:          System.out.println("Caught: " + e.getMessage());
10:         for (Throwable t: e.getSuppressed())
11:            System.out.println("Suppressed: " + t.getMessage());
12:      } } }
  • A. Caught: Cage door does not close / Suppressed: Turkeys ran off
  • B. Caught: Turkeys ran off / Suppressed: Cage door does not close
  • C. Caught: Turkeys ran off (nothing suppressed)
  • D. An uncaught exception is printed.
Show Answer B

The try block's exception is thrown first, so it is the primary. The exception from the automatic close() call is tacked on as suppressed. The catch matches the primary and prints both.

Q20Suppressed

Using the same JammedTurkeyCage (whose close() throws IllegalStateException), what happens here?

try (JammedTurkeyCage t = new JammedTurkeyCage()) {
   throw new RuntimeException("Turkeys ran off");
} catch (IllegalStateException e) {
   System.out.println("caught: " + e.getMessage());
}
  • A. Prints caught: Turkeys ran off.
  • B. Prints caught: Cage door does not close.
  • C. The RuntimeException propagates to the caller uncaught.
  • D. The code does not compile.
Show Answer C

The catch clause is matched against the primary exception, which is the RuntimeException from the try block — not the suppressed IllegalStateException from close(). Since RuntimeException is not an IllegalStateException, nothing matches and it propagates (with the suppressed exception attached).

Q21Suppressed

What is printed by this snippet (same JammedTurkeyCage)?

try (JammedTurkeyCage t = new JammedTurkeyCage()) {
   throw new IllegalStateException("Turkeys ran off");
} finally {
   throw new RuntimeException("and we couldn't find them");
}
  • A. "Turkeys ran off" propagates with "and we couldn't find them" suppressed.
  • B. Only "and we couldn't find them" propagates; the others are lost.
  • C. "Cage door does not close" propagates as the primary.
  • D. The code does not compile.
Show Answer B

Suppression only applies to exceptions from the try clause (and the automatic close). An exception thrown in a programmer-defined finally simply replaces whatever came before — the try-block exception and its suppressed close() exception are both lost.

Q22DecimalFormat

What is the output?

double d = 1234.567;
NumberFormat f2 = new DecimalFormat("000,000,000.00000");
System.out.println(f2.format(d));
  • A. 1,234.567
  • B. 000,001,234.56700
  • C. 001,234.56700
  • D. 000001234.56700
Show Answer B

The 0 symbol forces a digit (zero if absent) at every position, so the value is padded to nine integer digits with grouping commas and five decimal digits: 000,001,234.56700. With # instead, unused positions would simply be omitted.

Q23DecimalFormat

What does this print?

double d = 1234.567;
NumberFormat f3 = new DecimalFormat("Your Balance $#,###,###.##");
System.out.println(f3.format(d));
  • A. Your Balance $1,234.56
  • B. Your Balance $0,001,234.57
  • C. Your Balance $1,234.57
  • D. An IllegalArgumentException is thrown at runtime.
Show Answer C

Unused # positions (and the commas between them) disappear, and the fraction is rounded to two places: .567 → .57 (not truncated, so A is wrong). Literal prefix text like "Your Balance $" is printed as-is.

Q24Date Patterns

What is the result of the following?

var dt = LocalDateTime.of(2025, Month.OCTOBER, 20, 6, 15, 30);
var f = DateTimeFormatter.ofPattern("hh:mm:z");
System.out.println(dt.format(f));
  • A. 06:15:EDT
  • B. The code does not compile.
  • C. An exception is thrown at runtime.
  • D. 06:15: (zone omitted).
Show Answer C · DateTimeException

The pattern compiles fine, but z (time-zone name) requires zone information that a LocalDateTime doesn't have — so a DateTimeException is thrown at runtime. A ZonedDateTime would print something like 06:15 EDT.

Q25Date Patterns

Given dt = LocalDateTime.of(2025, Month.OCTOBER, 20, 6, 15, 30), what does this print?

var g1 = DateTimeFormatter.ofPattern("MMMM dd', Party''s at' hh:mm");
System.out.println(dt.format(g1));
  • A. October 20, Party's at 06:15
  • B. October 20, Party''s at 06:15
  • C. An IllegalArgumentException is thrown.
  • D. 10 20, Party's at 06:15
Show Answer A

Text inside single quotes is escaped literally, and '' (two single quotes) produces one literal quote. MMMM gives the full month name, dd the two-digit day, hh the 12-hour clock: October 20, Party's at 06:15.

Q26Locales

Which of the following are valid printed representations of a Locale? (Choose all that apply.)

  • A. US
  • B. enUS
  • C. en_US
  • D. EN
  • E. en
  • F. US_en
Show Answer C, E

The lowercase language code is mandatory; the UPPERCASE country code is optional and joined by an underscore. US lacks a language, enUS lacks the underscore, EN is uppercase, and US_en is reversed.

Q27NumberFormat

What is the result of the following?

String s = "40.45";
var fr = NumberFormat.getInstance(Locale.FRANCE);
System.out.println(fr.parse(s));   // assume ParseException is declared
  • A. 40.45
  • B. 40,45
  • C. 40
  • D. A ParseException is thrown at runtime.
Show Answer C · 40

France doesn't use a dot as a decimal separator. Java treats the . as a formatting character and stops parsing there, returning 40. Also remember: parse() throws a checked ParseException, so it must be handled or declared.

Q28Compact Numbers

What is printed? (Choose all that apply — one option per line of output.)

var compact = NumberFormat.getCompactNumberInstance(
   Locale.of("en", "US"), Style.SHORT);
System.out.println(compact.format(314_900_000));
System.out.println(compact.parse("1,000,000"));   // ParseException declared
  • A. 314M
  • B. 315M
  • C. 1000000
  • D. 1
  • E. A ParseException is thrown by the parse call.
Show Answer B, D

CompactNumberFormat keeps up to the first three digits of the range and rounds the last: 314.9 million → 315M. Parsing "1,000,000" stops at the comma and returns 1 — surprising but true. (A $ prefix, by contrast, would throw ParseException.)

Q29Resource Bundles

The default locale is en_US and the requested locale is fr_FR. In what order does Java search for the Zoo resource bundle?

  • A. Zoo_fr_FR → Zoo_fr → Zoo → Zoo_en_US → Zoo_en
  • B. Zoo_en_US → Zoo_en → Zoo_fr_FR → Zoo_fr → Zoo
  • C. Zoo_fr_FR → Zoo_fr → Zoo_en_US → Zoo_en → Zoo
  • D. Zoo → Zoo_fr → Zoo_fr_FR → Zoo_en → Zoo_en_US
Show Answer C

Requested locale first (language/country, then language), then the default locale the same way, and the no-locale default bundle Zoo.properties last. If nothing is found, a MissingResourceException is thrown.

Q30Resource Bundles

Given these properties files, what does rb.getString("name") print?

# Zoo.properties        → name=Vancouver Zoo
# Zoo_en.properties     → hello=Hello, open=is open
# Zoo_en_US.properties  → name=The Zoo
# Zoo_en_CA.properties  → visitors=Canada visitors

Locale.setDefault(Locale.of("en", "US"));
var rb = ResourceBundle.getBundle("Zoo", Locale.of("en", "CA"));
System.out.print(rb.getString("name"));
  • A. The Zoo
  • B. Vancouver Zoo
  • C. A MissingResourceException is thrown.
  • D. null
Show Answer B · Vancouver Zoo

The matched bundle is Zoo_en_CA, so keys may come only from its hierarchy: Zoo_en_CA → Zoo_en → Zoo. Neither of the first two defines name, so the base Zoo.properties supplies "Vancouver Zoo". Zoo_en_US (the default locale's file) is never consulted once a match is found.

Q31Properties

Which lines do not compile? (Choose all that apply.)

var props = new Properties();
props.setProperty("open", "10am");
1: System.out.println(props.getProperty("camel"));
2: System.out.println(props.getProperty("camel", "Bob"));

  • B. Line 2
  • C. Line 3

Only getProperty() has an overload with a default value. get() takes a single parameter, so line 4 does not compile. Line 1 compiles and prints null; line 2 prints Bob; line 3 prints 10am.

Q32Locale.Category

After the following, how is NumberFormat.getCurrencyInstance().format(1.23) displayed, and what does spain.getDisplayLanguage() show?

var spain = Locale.of("es", "ES");
Locale.setDefault(Locale.of("en", "US"));
Locale.setDefault(Category.DISPLAY, spain);
// FORMAT category still en_US
  • A. 1,23 € and español
  • B. $1.23 and español
  • C. $1.23 and Spanish
  • D. 1,23 € and Spanish
Show Answer B

Only the DISPLAY category was switched to Spanish, so language names display as español — but currency formatting follows the FORMAT category, which is still en_US: $1.23. Setting Category.FORMAT too would give 1,23 €.

★ Quick Revision — Chapter 11 Core Traps

  • Checked = Exception minus RuntimeException → handle or declare; declaring an unused checked exception is legal, but catching an impossible one is not.
  • throw new … — no new, no compile. Code after a throw in the same block = unreachable.
  • Catch order: subclass before superclass (NFE ⊂ IAE, FNFE ⊂ IOException). Multi-catch: one variable at the end, no related types, order irrelevant.
  • finally always runs (except System.exit()) — and a return there overrides try/catch returns.
  • Try-with-resources: AutoCloseable only, ;-separated with types, closes in reverse order via an implicit finally that runs before catch/finally; resource scope = try block; pre-declared resources must be (effectively) final.
  • Suppressed: first thrown = primary (catch matches this one); close() failures are suppressed; a throw in a programmer's finally replaces everything.
  • DecimalFormat: # omits, 0 pads, fractions round. Date symbols are case-sensitive (M/m, H/h); wrong symbol for the type → runtime exception; escape literals with '…', '' = literal quote.
  • Locale = lowercase language (required) + optional _UPPERCASE country; constructors deprecated. parse() throws checked ParseException and is locale-sensitive (fr "40.45" → 40). Compact = 3 digits + K/M/B/T, SHORT by default, rounds the third digit.
  • Bundle search: requested (full → lang) → default (full → lang) → base → MissingResourceException; values then come only from the matched hierarchy + parents.
  • Properties: only getProperty() takes a default; two-arg get() does not compile.

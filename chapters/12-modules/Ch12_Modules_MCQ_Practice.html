Q1Module structure

Which statement is true of the following directory structure?

|--- aquarium
   |-- fish
      |-- Feeder.java
  • A. The directory structure shown is already a valid module.
  • B. It would be a valid module if module-info.java were added directly underneath aquarium.
  • C. It would be a valid module if module-info.java were added directly underneath aquarium/fish.
  • D. It would be a valid module if module.java were added directly underneath aquarium.
Show Answer
B

Every module requires a module-info.java file at the root directory of the module. Here aquarium is the module directory and fish is the package, so the file goes directly under aquarium. C puts it inside a package, and D uses the wrong filename — it is always module-info.java.

Q2Directives

Module puppy depends on module dog, and dog depends on module animal. Fill in the blank so that code in module dog can access the animal.behavior package.

module animal {
   _________ animal.behavior;
}
  • A. export
  • B. exports
  • C. requires
  • D. requires transitive
Show Answer
B

exports is the directive that allows a package to be called by code outside the module. A is not a directive — the keyword is always plural. C and D are the wrong keyword entirely: requires names a module you depend on, never a package you publish.

Q3Command line

Which command correctly runs class Peacocks in package zoo.animal.talks, inside module zoo.animal.talks, with the modules in the mods folder?

  • A. java -d mods -m zoo.animal.talks/zoo.animal.talks.Peacocks
  • B. java -p mods -m zoo.animal.talks/zoo/animal/talks/Peacocks
  • C. java -p mods -m zoo.animal.talks/zoo.animal.talks.Peacocks
  • D. java -m mods -p zoo.animal.talks/zoo.animal.talks.Peacocks
Show Answer
C

-p (or --module-path) gives the module location and -m (or --module) gives moduleName/fully.qualified.ClassName. B uses slashes inside the class name — package parts must use periods. A uses -d, which on java means --describe-module. D swaps the two options.

Q4Services

Which of the following pairs make up a service?

  • A. Consumer and service locator
  • B. Consumer and service provider interface
  • C. Service locator and service provider
  • D. Service locator and service provider interface
Show Answer
D

A service consists of the service provider interface (plus any classes it references) and the lookup logic in the service locator. The service provider is the implementation and is explicitly not part of the service, which rules out C. The consumer merely calls the service, ruling out A and B.

Q5Module types

A(n) __________ module is on the classpath while a(n) __________ module is on the module path.

Choose all that apply.

  • A. automatic, named
  • B. named, unnamed
  • C. unnamed, automatic
  • D. unnamed, named
Show Answer
C · D

Unnamed modules live on the classpath. Both automatic and named modules live on the module path — automatic without a module-info.java, named with one. A and B are wrong because they place a module-path type on the classpath.

Q6Directives

Which of the following statements are true in a module-info.java file?

Choose all that apply.

  • A. The opens directive allows the use of reflection.
  • B. The opens directive declares that an API is called.
  • C. The uses directive allows the use of reflection.
  • D. The uses directive declares that an API is called.
Show Answer
A · D

opens is for reflection; uses declares that the module consumes a service, referencing the service provider interface so the locator can find it. B and C simply swap the two meanings.

Q7Automatic names

An automatic module name is generated when the manifest does not supply one. Which JAR filename / generated name pairs are correct?

Choose all that apply.

  • A. emily-1.0.0.jar and emily
  • B. emily-1.0.0-SNAPSHOT.jar and emily
  • C. emily_the_cat-1.0.0.jar and emily_the_cat
  • D. emily.$.jar and emily
Show Answer
A · B · D

Version information at the end of the filename is removed, including a trailing tag like -SNAPSHOT, so A and B are right. C is wrong because underscores are special characters and become dots — the name is emily.the.cat. In D the $ becomes a dot giving emily.., adjacent dots merge to emily., and the trailing dot is removed.

Q8Cyclic deps

Which of the following statements are true?

Choose all that apply.

  • A. Modules with cyclic dependencies will not compile.
  • B. Packages with a cyclic dependency will not compile.
  • C. A cyclic dependency always involves exactly two modules.
  • D. A cyclic dependency always involves at least two requires statements.
Show Answer
A · D

The JPMS forbids cycles between modules, so A is correct, and forming a cycle needs at least two requires statements, so D is correct. No such restriction applies to packages inside a module, making B wrong, and a cycle can span three or more modules, making C wrong.

Q9Services

You are creating a service provider containing this class. Which line belongs in your module-info.java?

package dragon;
import magic.*;
public class Dragon implements Magic {
   public String getPower() {
      return "breathe fire";
   }
}
  • A. provides dragon.Dragon with magic.Magic;
  • B. provides magic.Magic with dragon.Dragon;
  • C. provides magic.Magic using dragon.Dragon;
  • D. uses magic.Magic with dragon.Dragon;
Show Answer
B

The provides directive takes the interface first and the implementing class second, joined by with. A reverses the two, C invents a using keyword, and D misuses uses, which takes a single interface name and no second operand.

Q10exports

What is true of a module containing a module-info.java file with the following contents?

module com.food.supplier {}

Choose all that apply.

  • A. No packages inside the module are automatically exported.
  • B. All packages inside the module are automatically exported.
  • C. A main() method inside the module can be run.
  • D. The module-info.java file contains a compiler error.
Show Answer
A · C

Packages are never exported by default, so A is correct and B is wrong. Exporting is only needed for other code to use the packages — it is not needed to launch a main() method from the command line, so C is correct. The declaration is syntactically valid, so D is wrong.

Q11requires transitive

Which of these individually appear in a correct solution that lets module puppy access the animal.behavior package?

module animal {
   exports animal.behavior;
}
module dog {
   _____________ animal;   // line S
}
module puppy {
   _____________ dog;      // line T
}

Choose all that apply.

  • A. requires on line S
  • B. requires on line T
  • C. requires transitive on line S
  • D. requires transitive on line T
Show Answer
B · C · D

Line S must be requires transitive so that the dependency on animal is passed along to anything requiring dog — hence C. On line T a plain requires dog is enough to inherit that transitive dependency (B), and requires transitive also works there since it does everything requires does and more (D). A plain requires on line S (option A) would keep the dependency private to dog.

Q12Built-in modules

Which of the following are modules provided by the JDK?

Choose all that apply.

  • A. java.base
  • B. java.util
  • C. jdk.compiler
  • D. jdk.base
Show Answer
A · C

java.base and jdk.compiler are both real JDK modules. B is a trap: java.util is a package that lives inside java.base, not a module. D is invented — the base module is java.base, never jdk.base.

Q13ServiceLoader

Which compiles and is equivalent to this loop?

List<Unicorn> all = new ArrayList<>();
for (Unicorn current : ServiceLoader.load(Unicorn.class))
   all.add(current);
  • A. ServiceLoader.load(Unicorn.class).getStream().toList();
  • B. ServiceLoader.load(Unicorn.class).stream().toList();
  • C. ServiceLoader.load(Unicorn.class).stream().map(Provider::get).toList();
  • D. ServiceLoader.load(Unicorn.class).getStream().map(Provider::get).toList();
Show Answer
C

There is no getStream() method on ServiceLoader, which eliminates A and D. stream() returns a Stream<Provider<S>>, so B produces a list of Provider objects rather than List<Unicorn> and does not compile. C converts each Provider with get() first.

Q14Command line

Which is a legal command to run a modular program, where n is the module name and c is the fully qualified class name?

  • A. java --module-path x -m n.c
  • B. java --module-path x -p n/c
  • C. java --module-path x-x -m n/c
  • D. java --module-path x -m n-c
Show Answer
C

The module name and class name must be separated with a slash, so C is correct — and x-x is fine because the module path is a folder name, where dashes are allowed. A uses a period instead of the slash, B repeats the module-path option (-p is the short form of --module-path), and D uses a dash as the separator.

Q15Migration

For a top-down migration, all modules other than named modules are __________ modules and are on the __________.

  • A. automatic, classpath
  • B. automatic, module path
  • C. unnamed, classpath
  • D. unnamed, module path
Show Answer
B

A top-down migration begins by placing all JARs on the module path, then converts the top-level project to a named module. Anything not yet migrated sits on the module path without a module-info.java, which is the definition of an automatic module. Unnamed modules belong to bottom-up migration, which leaves unmigrated JARs on the classpath.

Q16Services

You have separate modules for a service provider interface, service provider, service locator, and consumer. If you add a second service provider module, how many of the existing modules do you need to recompile?

  • A. Zero
  • B. One
  • C. Two
  • D. Four
Show Answer
A

You compile the new module itself, but none of the existing modules change. The service locator discovers the new provider at runtime simply because it is present on the module path — that is the whole point of the loose coupling a service gives you.

Q17Module types

Suppose you have a JAR named cat-1.2.3-RC1.jar, and Automatic-Module-Name in its MANIFEST.MF is set to dog. What should an unnamed module referencing this automatic module include in its module-info.java?

  • A. requires cat;
  • B. requires cat.RC;
  • C. requires dog;
  • D. None of the above
Show Answer
D

Trick question. An unnamed module has no module-info.java at all — that is what makes it unnamed. It can still access the automatic module, but it treats it as a plain JAR without any module declaration. Had the question been about a named module, the manifest name dog would win over the filename.

Q18Tooling

Two commands create artifacts that include smaller versions of the JDK. Which are used to create an .exe file and a directory, respectively?

  • A. jimage and jlink
  • B. jlink and jpackage
  • C. jpackage and jlink
  • D. jpackage and jimage
Show Answer
C

jpackage creates a self-contained application image such as an .exe or .dmg; jlink creates a directory holding a smaller Java runtime containing just what is needed. jimage only inspects a Java image file, so A and D are wrong, and B reverses the correct pair.

Q19Compile error

Which is a true statement about the following module?

class dragon {
   exports com.dragon.fire;
   exports com.dragon.scales to castle;
}
  • A. All modules can reference the com.dragon.fire package.
  • B. Only the castle module can reference the com.dragon.scales package.
  • C. Both A and B are true.
  • D. None of the above.
Show Answer
D

A module definition must use the keyword module, not class, so this code does not compile and no statement about its exports can be true. If the keyword were fixed, C would then be the correct description.

Q20Describe module

Which line would you expect to see when describing any module?

  • A. requires java.base mandated
  • B. requires mandated java.base
  • C. requires java.lang mandated
  • D. requires java.core mandated
Show Answer
A

Describing a module lists its required modules, and java.base always appears because it is added automatically — with mandated at the end of the line, which rules out B. C is a trap: java.lang is a package imported by default in a class, not a module. There is no java.core module.

Q21Services

You have separate modules for a service provider interface, service provider, service locator, and consumer. Which module(s) need to specify a requires directive on the service provider?

  • A. Service locator
  • B. Consumer
  • C. Consumer and service locator
  • D. None of the above
Show Answer
D

No module requires the service provider — it is the implementation, and it is discovered at runtime by ServiceLoader. The service locator does have a uses directive, but it names the service provider interface, not the provider. Both the locator and the consumer requires the interface module.

Q22Module types

Which are true statements?

Choose all that apply.

  • A. An automatic module exports all packages to named modules.
  • B. An automatic module exports only the specified packages to named modules.
  • C. An unnamed module exports all packages to named modules.
  • D. An unnamed module exports no packages to named modules.
Show Answer
A · D

An automatic module exports everything, since there is no module-info.java to restrict it, making A correct and B wrong. An unnamed module is on the classpath and is not available to anything on the module path, so it exports no packages to named modules — D is correct and C is wrong.

Q23Compile error

Which is the first line to contain a compiler error?

1: module snake {
2:    exports com.snake.tail;
3:    exports com.snake.fangs to bird;
4:    requires skin;
5:    requires transitive skin;
6: }
  • A. Line 3
  • B. Line 4
  • C. Line 5
  • D. The code does not contain any compiler errors.
Show Answer
C

The module name and both exports statements are valid, and a qualified export on line 3 is fine. Lines 4 and 5 are each legal on their own, but the same module name may not appear in two requires statements — so the second one, line 5, is what fails to compile.

Q24Module types

Which is a true statement about a package in a JAR on the classpath that contains a module-info.java file?

  • A. It is possible to make the package available to all other modules on the classpath.
  • B. It is possible to make the package available to all other modules on the module path.
  • C. It is possible to make the package available to exactly one other specific module on the classpath.
  • D. It is possible to make sure the package is not available to any other modules on the classpath.
Show Answer
A

Because the JAR is on the classpath it is an unnamed module and the module-info.java inside is ignored — so everything on the classpath sees everything, making A correct. B is wrong since modules on the module path cannot refer to the classpath. The classpath has no facility to restrict packages at all, which rules out C and D.

Q25Services

You have separate modules for a service provider interface, service provider, service locator, and consumer. Which statements are true about the directives you need to specify?

Choose all that apply.

  • A. The consumer must use the requires directive.
  • B. The consumer must use the uses directive.
  • C. The service locator must use the requires directive.
  • D. The service locator must use the uses directive.
Show Answer
A · C · D

Both the consumer and the service locator depend on the service provider interface module, so both need requires — A and C. The locator is the one performing the lookup, so it also needs uses — D. The consumer never declares uses; the locator handles discovery on its behalf, so B is wrong.

Q26Output

The zoo.tours.api, zoo.tours.reservations, and zoo.visitor modules are all on the module path, but no service provider module has been created yet. What is the result of running Tourist?

public static void main(String[] args) {
   Tour tour = TourFinder.findSingleTour();
   System.out.println("Single tour: " + tour);

   List<Tour> tours = TourFinder.findAllTours();
   System.out.println("# tours: " + tours.size());
}
  • A. It prints Single tour: null then # tours: 0
  • B. It throws a NullPointerException on the first println
  • C. It prints Single tour: null then throws a NullPointerException
  • D. The code does not compile without a provides directive
Show Answer
A

findSingleTour() finds no providers, so the enhanced for loop body never executes and null is returned; concatenating a null reference into a String prints the text null rather than throwing. findAllTours() returns an empty ArrayList, not null, so size() is 0.

Q27opens

What is the result of the following module declaration?

open module zoo.animal.talks {
   opens zoo.animal.talks.schedule;
}
  • A. It compiles, and every package in the module is open for reflection.
  • B. It compiles, and only zoo.animal.talks.schedule is open for reflection.
  • C. It does not compile.
  • D. It compiles, but the opens directive is ignored at runtime.
Show Answer
C

A module declared with the open modifier is not permitted to also use the opens directive — all of its packages are open already, so the directive is redundant and rejected. Remove either the open modifier or the opens line and it compiles.

Q28Command line

Which commands describe the module in mods/zoo.animal.feeding.jar?

Choose all that apply.

  • A. java -p mods -d zoo.animal.feeding
  • B. java -p mods --describe-module zoo.animal.feeding
  • C. jar -f mods/zoo.animal.feeding.jar -d
  • D. javac -p mods -d zoo.animal.feeding
Show Answer
A · B · C

On both java and jar, -d is the short form of --describe-module, so A, B, and C all work — the jar output differs only by including module-info.class in the filename. D is the trap: on javac, -d specifies the output directory for class files.

Q29Command line

Which statements about these two java options are true?

Choose all that apply.

  • A. --list-modules prints the observable modules and exits without running the program.
  • B. --show-module-resolution prints resolution details and then runs the program.
  • C. --list-modules only works when -p is also supplied.
  • D. Both options belong to the java command.
Show Answer
A · B · D

--list-modules exits as soon as it prints, while --show-module-resolution outputs the resolution trace and then executes, ending with the program's own output. Both are java options. C is wrong: java --list-modules on its own lists the JDK modules, and adding -p merely appends your custom ones.

Q30jdeps

Which are valid jdeps invocations against zoo.dino.jar?

Choose all that apply.

  • A. jdeps -s zoo.dino.jar
  • B. jdeps -summary zoo.dino.jar
  • C. jdeps -jdkinternals zoo.dino.jar
  • D. jdeps -p mods zoo.dino.jar
Show Answer
A · B · C

-s and -summary are equivalent summary flags, and -jdkinternals is equivalent to --jdk-internals, which lists uses of internal APIs such as sun.misc.Unsafe. D is the trap: unlike other commands, jdeps has no short form for --module-path.

Q31Access control

Given this declaration, can a public class in zoo.animal.care.details be referenced from module zoo.staff, which declares requires zoo.animal.care;?

module zoo.animal.care {
   exports zoo.animal.care.medical;
   requires zoo.animal.feeding;
}
  • A. Yes, because the class is declared public.
  • B. Yes, because zoo.staff requires zoo.animal.care.
  • C. No, because the package is not exported.
  • D. No, because a module may export only one package.
Show Answer
C

A public type is accessible outside its module only if its package is exported, and only zoo.animal.care.medical is. requires grants access to what the other module exports, so B does not help. D is false — a module can export as many packages as it likes, one exports statement each.

Quick Revision — the chapter's core traps

  • Declaration basics: keyword module (never class), file named module-info.java, placed in the module's root, module names allow dots but never dashes.
  • Directive spelling: exports, requires, opens, provides … with …, uses — all plural, any order. export, require, and use do not exist.
  • Does not compile: the same module in two requires clauses (error on the second), and open module combined with an opens directive.
  • Access: public reaches outside the module only if the package is exported. An unexported package still lets you run its main() from the command line.
  • Services: the service = SPI + locator. Provider and consumer are outside it. Nobody requires the provider; adding one costs zero recompiles.
  • ServiceLoader: iterable directly; stream() gives Stream<Provider<S>>, so .map(Provider::get) is mandatory. There is no getStream().
  • Command line: -p/--module-path, -m/--module with module/fully.qualified.Class — one slash, dots everywhere else. -d means output directory on javac but --describe-module on java and jar.
  • Tooling: jdeps (-s, -jdkinternals, no short --module-path), jmod for JMOD files, jlink → directory, jpackage → executable, jimage only inspects.
  • Module types: named (module-info + module path), automatic (no module-info + module path, exports all), unnamed (classpath, exports nothing to named modules, ignores any module-info inside).
  • Automatic names: manifest wins; otherwise drop extension and version, turn special characters into dots, collapse repeats, trim leading/trailing dots.
  • Migration: bottom-up leaves unmigrated JARs unnamed on the classpath; top-down puts everything on the module path so unmigrated JARs are automatic.
  • Cycles: never allowed between modules (won't compile), always allowed between packages inside one module.
